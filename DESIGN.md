# DESIGN.md — CloudCLI UI design system

Read this before any UI work. Reuse the closest existing element listed below; a new variant extends the existing pattern, never a parallel style.

One design across form factors: the desktop-only gating from UI rounds 1–3 is removed, so mobile renders the same language (radius token, silver-blue accent, unified composer with Handoff, grouped model switcher, usage ring + left-anchored popover, tool-row treatment, sidebar segmented control and bottom-pinned Settings, self-hosted font). Mobile-only functional controls with no desktop equivalent (tab rail, drawers, bottom sheets, keyboard insets, the Running view, create-project) stay, restyled with these same tokens — never a parallel style.

## Tokens

All color tokens are HSL triplets consumed as `hsl(var(--token))`, defined in `src/index.css` (`:root` = light, `.dark` = dark) and mapped to Tailwind utilities in `tailwind.config.js`.

### Typography

Self-hosted Schibsted Grotesk Variable (weights 400–900, normal + italic) via `@fontsource-variable/schibsted-grotesk`, imported at the top of `src/index.css`. No CDN font dependencies.

- `--font-ui` — UI chrome. Tailwind `font-sans` (the body default).
- `--font-message` — chat message content. Tailwind `font-serif` (legacy utility name kept so existing call sites resolve to the message cut; do not add real serifs).

Both currently point at the same family; keep them separate so the cuts can diverge.

### Radius

- `--radius: 0.5rem` (8px) — the one app-wide corner radius token. Tailwind `rounded-lg` = token, `rounded-md` = token − 2px, `rounded-sm` = token − 4px. Do not use `rounded-xl`/`rounded-2xl` on standard surfaces; desktop surfaces that carried hardcoded 12px radii were migrated to `rounded-lg`.
- Never apply asymmetric per-corner radii (`rounded-br-*` etc.) in the chat view. Fully-round pills/avatars use `rounded-full`.

### Colors (semantic, light/dark via `.dark`)

`--background` / `--foreground`, `--card`, `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring` — each with a `-foreground` pair where applicable. Nav-specific glass tokens (`--nav-glass-*`, `--nav-tab-*`, `--nav-input-*`) also live in `src/index.css`.

- Accent: silver-leaning silver-blue. Light `--primary: 211 20% 45%` (`--primary-foreground` white); dark `--primary: 211 22% 64%` (`--primary-foreground` near-black, the lighter accent needs dark type). `--ring` and the nav glow/focus tokens carry the same hue per theme. Every accent use (send button, links, active states, selection ticks, progress ring fill, focus rings) goes through `primary`/`ring` utilities — never hardcode blue or orange Tailwind palette classes. Warning states use the amber family; nothing uses the orange family.
- User message bubble: `bg-secondary text-secondary-foreground` (lighter gray bubble on the darker background in dark mode, white text). No blue bubble, no avatar circle.
- Secondary/metadata text: `text-muted-foreground`.

### Shadow & spacing

- Bubbles and inline chat elements: flat, no shadow beyond what the component already carries.
- Popovers/menus: `border border-border bg-popover shadow-lg` with `rounded-md`/`rounded-lg`.
- Mobile safe-area and nav spacing variables (`--mobile-nav-*`, `--safe-area-inset-*`) are defined in `src/index.css`; use them, don't hardcode offsets.

## Reusable-element inventory

Shared primitives (shadcn-style, use these first): `src/shared/view/ui/`
- `Button.tsx`, `Input.tsx`, `Badge.tsx`, `Card.tsx`, `Alert.tsx`, `Dialog.tsx`, `Tooltip.tsx`, `Collapsible.tsx`, `ScrollArea.tsx`, `Command.tsx`, `ActionMenu.tsx`, `PillBar.tsx`, `PromptInput.tsx`, `Reasoning.tsx` (thinking accordion), `Shimmer.tsx`, `Confirmation.tsx` — exported through `src/shared/view/ui/index.ts`. (`Queue.tsx` was retired; task lists render through the beUI `TodoList`.)
- `Badge.tsx` carries the beUI animated-badge skin — rounded-full pill, `font-medium tabular-nums`, tinted `border-{color}/30 bg-{color}/10` colorways through semantic tokens (primary for default/info/loading, destructive for danger, emerald for success, amber for warning). Passing `status` opts into the animated state treatment: rolling icon/text swaps on status change, spinning loader with pulse for in-progress states; suppressed under prefers-reduced-motion. Wired on the worker/planner header state pills and the tool-row `ToolStatusBadge` — never invent status badges elsewhere.

Chat view: `src/components/chat/view/`
- `ChatInterface.tsx` — top-level chat screen.
- `subcomponents/MessageComponent.tsx` — one message (user bubble, assistant/tool/error layouts).
- `subcomponents/MessageCopyControl.tsx` — single copy button, always copies plain text.
- `subcomponents/MessageSpeakControl.tsx` — TTS button.
- `subcomponents/Markdown.tsx` — markdown renderer (`prose prose-sm font-serif dark:prose-invert` pattern). Fenced code renders in the beUI code-block chrome: `rounded-lg bg-muted/80` panel, `h-10` header (file icon, uppercase language tag, circular hover copy button with check swap), `border-t border-foreground/[0.06]` code viewport capped at 280px with internal scroll.
- `subcomponents/ChatComposer.tsx` — input composer (unified single box: textarea on top, one control row below; plus/attach left, model selector + send right; no hint text, no permission selector — sessions are hardwired to skip-permissions). At rest the box is exactly one text line tall (`rows={1}` textarea) and autogrows upward as content wraps. Focus state is a quiet gray (`focus-within:border-muted-foreground/40` + `ring-muted-foreground/20`), not the accent. The slash-commands icon is a custom single diagonal stroke matching the plus icon's arm length and stroke width; a Handoff button (document icon, `FileTextIcon`, all form factors, planner project chats only — hidden in the worker pane and standalone/scratch chats) sits immediately right of it and fires the `/handoff` user command through `/api/commands/execute`. A character counter (`data-slot="char-counter"`, `text-[10px] tabular-nums text-muted-foreground`, digits rolling through `NumberTicker`) sits left of the model pill whenever the input is non-empty. A text paste over 2,000 characters collapses into a "Pasted text.txt" attachment chip (Claude-desktop style) instead of flooding the textarea, and is delivered through the existing attachment path (`/api/assets/files` upload + `<files_input>` reference). `ComposerModelMenu.tsx` — Claude.ai-style model switcher (pill: friendly name + effort + chevron; card + Effort and More models submenus; friendly labels only, wire values unchanged). More models hides the selected model (it renders as the checked card above) and splits the rest into current and legacy groups separated by a `ComposerMenuSeparator`, driven by the `group` field on the one plain catalog array in `server/modules/providers/list/claude/claude-models.provider.ts` (id, friendly name, tagline, group, in display order), `CommandMenu.tsx` — composer menus (portal + `bg-popover` pattern).
- `src/shared/view/beui/` — the vendored beUI kit (beui.dev), rethemed to this app's tokens: `MessageScroller` (follow-output transcript scroller — ResizeObserver keeps the live edge pinned, smooth-scrolling as streamed content grows), `StreamingResponse`/`useStreamedReveal` (live-turn reveal at ~126 chars/s), `BrailleLoader` (horizontal ASCII Braille loader), `AgentDisclosure` (transform-only collapsible reveal), `SwapText` (roll label swap), `textShimmer` (the one text-shimmer treatment for in-progress labels), `ease.ts` (the motion springs/easings — use these, never ad-hoc curves). Phase-4 additions: `ActionSwapIcon` (blur icon swap for state-changing controls), `BeuiSwitch`, `BeuiTabs` (pill/underline/segment tabs with the `TABS_INDICATOR_SPRING` layoutId indicator), `BeuiSelect` (bouncy unfold select), `BeuiRadio` (`RadioGroup`/`RadioDot` gliding indicator), `NumberTicker` (rolling digit columns for live counts), `Loader` (dot-matrix + dither loading marks), `TodoList`, `Citations` + `useFavicon`, `ToolApproval`. New collapsibles, controls, and loaders on the chat surface extend this kit.
- Control laws from the phase-4 adoption: any control whose icon changes with state renders it through `ActionSwapIcon`, never a hard cut (composer submit send/stop/queue, voice mic). Values that change while the user watches (composer character counter, activity-indicator elapsed time, context-popover header value) render through `NumberTicker` with a `format` callback — digits roll in place, unit glyphs (`k`, `M`, `%`, `m`, `s`) render as plain text, so the displayed string is byte-identical to the static version. Every true loading overlay or pinned loading state (chat transcript, sidebar, code/PRD editor overlays, shell connection overlay, git panel views) uses the beUI `Loader` (`dot-matrix` app-wide, `dither` on shell/terminal surfaces); inline button spinners keep `Loader2`/spin. The composer model-switcher pill rolls its model/effort labels through `SwapText` on selection.
- `BeuiSwitch` is the one toggle: h-7 w-12 track `rounded-md`, h-5 w-5 thumb `rounded-sm` (box radius, not a pill), checked `bg-primary`, spring-driven thumb with press squish-stretch; optional `thumbContent` centers an icon in the thumb (DarkModeToggle's Moon/Sun). `SettingsToggle` and `DarkModeToggle` delegate to it.
- Tabs: `BeuiTabs` — a spring `layoutId` indicator glides between triggers. Underline variant (h-px `bg-primary`) drives GitViewTabs; segment variant (`bg-primary` pill on the rounded-md step) drives MainContentTabSwitcher inside the old muted bar chrome; the Settings desktop sidebar reuses the same spring for its gliding `bg-accent` row highlight. The sidebar segmented control (`PillBar`) is untouched pending the phase-5 sidebar steal.
- Selects: `BeuiSelect` replaces native `<select>`s — the panel bouncily unfolds out of the trigger and flips upward when out of room. Trigger `rounded-lg border-input bg-card` with `ring` focus; panel on the popover spec; selected tick `text-primary`. Homes: Appearance tab selects, LanguageSelector.
- Radio: `BeuiRadio`'s `RadioDot` — ring-and-dot whose inner `bg-primary` dot glides between options via shared `layoutId`. AskUserQuestionPanel's single-select rows compose it with `SPRING_PRESS` tap feedback; multi-select rows keep the checkmark.
- Context menus: the file-tree right-click menu unfolds with the beUI clip-path morph — the panel expands from an 8px-radius window at the cursor point (0.3s EASE_OUT), items use the spring shared-layout highlight instead of hover backgrounds, and danger items use the rose error colorway. Panel: `min-w-56 p-1.5 rounded-lg border-border bg-popover`; `data-slot="context-menu"`. Keyboard opens and reduced motion skip the morph.
- Tool-permission prompts: `PermissionRequestsBanner` renders pending requests through the vendored beUI tool-approval card (`ToolApproval.tsx`, `data-slot="tool-approval"`): a `rounded-lg border-border/60 bg-muted/20` card with a shield tile, "Allow this tool to run?" title over the mono tool name, an amber "Approval required" pill, the allow-rule code chip, and a "View tool input" reveal via `AgentDisclosure` into the standard `rounded-lg bg-muted/80` mono viewport. Action row: Allow once solid, Allow & remember outlined, Deny ghost, with `SPRING_PRESS` tap feedback. AskUserQuestion still routes to its custom panel; ExitPlanMode stays with PlanDisplay.
- Task lists: `TodoList` (`data-slot="todo-list"`) — a bordered `rounded-lg` card with an `h-11` header (ListTodo icon that spring-swaps to an emerald check when all items complete, rolling `completed/total` count via `SwapText`, spring-rotated chevron) over an `AgentDisclosure` viewport capped at 248px. Rows carry animated SVG status circles: dashed pending, spinning arc in-progress, drawn check + strike-through completed. All TodoWrite/TodoRead tool rows render through it.
- Citations: `Citations` (`data-slot="citations"`) — a quiet "Sources" toggle revealing favicon rows (site favicon via `useFavicon` with a Globe fallback, title, domain, index chip) through `AgentDisclosure`. An assistant message whose markdown contains external http(s) links gets exactly one strip after the body, deduped by URL (`extractExternalLinks` in `chatFormatting.ts`); user messages, tool rows, and link-free messages never show it; inline prose links are untouched.
- `subcomponents/ActivityIndicator.tsx` — response-in-progress indicator: `BrailleLoader` left of a shimmering "thinking" label (server status text overrides the word) plus elapsed time.
- Message rows: new live rows enter with the beUI message pop-up spring (`MESSAGE_POP_UP`, rise-and-scale from the bottom edge); loaded history renders statically. Timestamps are right-aligned and hidden until row hover (`opacity-0 group-hover:opacity-100` fade; always visible on touch).
- `subcomponents/ChatMessagesPane.tsx` — scroll container (wraps the beUI `MessageScroller`); `TokenUsageSummary.tsx` — circular context-usage progress ring; click opens the context-usage popover (a "Context window" header row `<used>k / <limit> (<percent>)` with a chevron that expands the SDK-reported per-category breakdown; no billing/plan section). Ring and popover divide the same `used` by the same `total` (the SDK-reported window, persisted per model id in `app_config` when a live turn observes it and served on session load; env `CONTEXT_WINDOW` is only the never-observed fallback). The popover's left edge anchors to the ring button's left edge and opens upward on every form factor (`useComposerMenuAnchor` with `align: 'left'`; `maxWidth` shrinks it on narrow viewports). The composer commands button (slash icon) sits immediately left of the ring.
- `tools/ToolRenderer.tsx` (+ `tools/components/`) — tool input/result rendering. Every tool row (one-line, collapsible, Bash command row, grouped rows, subagent, error) carries the beUI tool-result treatment (beui.dev/components/agents/tool-result): a compact flush header row (muted icon or `$`, medium label, mono value in `text-muted-foreground`, status at right), a spring-rotated `ChevronDown` on the right when expandable, and content revealed through `AgentDisclosure` with a `pl-6` indent — expanded output/error bodies sit in a `rounded-lg bg-muted/80` viewport. Error rows use the rose status colorway (`text-rose-600 dark:text-rose-400`). No left rules, no per-category border colors.

App chrome
- Sidebar: `src/components/sidebar/`; main layout: `src/components/main-content/`, `src/components/app/`. The main chat pane and the worker pane each carry the same slim header bar (`border-b border-border/60 bg-muted/30 px-3 py-1.5`, muted icon + `text-xs font-medium` label): "Planner" with the open session's title in `MainContent.tsx` (label follows the open session's origin — a worker-origin session shows "Worker" with the Hammer icon), "Worker" with the run switcher in `WorkerPane.tsx`. Both headers carry fail-safe pills in the worker pane's state-pill style (`rounded-full border px-1.5 py-0.5 text-[10px]`, destructive colorway): "disconnected" while the websocket is down, "stream mismatch" if the rendered transcript diverges from the claimed session for over 2s. New pane-level headers extend this bar, never a parallel style. `SidebarHeader.tsx` is one shared header (equal-width segmented control in the top button bar + ghost icon cluster + search; mobile adds the Running segment and create-project button, desktop the collapse button); `SidebarFooter.tsx` is the single bottom-pinned Settings row on both form factors.
- Settings: `src/components/settings/`; quick settings: `src/components/quick-settings-panel/` (mobile-only edge flyout; desktop gets these settings in the Settings page's Appearance tab).

Global CSS (scrollbars, transitions, chat containment classes, placeholder colors): `src/index.css`.
