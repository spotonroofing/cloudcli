# DESIGN.md — CloudCLI UI design system

Read this before any UI work. Reuse the closest existing element listed below; a new variant extends the existing pattern, never a parallel style.

One design across form factors: the desktop-only gating from UI rounds 1–3 is removed, so mobile renders the same language (radius token, silver-blue accent, unified composer with Handoff, grouped model switcher, usage ring + left-anchored popover, tool-row treatment, sidebar segmented control and bottom-pinned Settings, self-hosted font). Mobile-only functional controls with no desktop equivalent (tab rail, drawers, bottom sheets, keyboard insets, the Running view, create-project) stay, restyled with these same tokens — never a parallel style.

Mobile parity laws (ui7 phase 8): the mobile sidebar project/session rows are the same beUI ai-sidebar row anatomy as desktop (borderless `min-h-11 rounded-lg` rows — 44px-tall touch variant of the desktop `min-h-9` — icon tile, MarqueeLabel, count numeral, spring chevron), with actions always visible instead of hover-revealed; session actions open the bottom sheet (rename / move / copy / delete on token colorways). The mobile top bar is hamburger + tab rail only, on the pane-header bar chrome — the old chat-title block is gone on both form factors; titles live in the pane header. The sidebar refresh button is desktop-only; mobile refreshes by pulling the sidebar list down (`usePullToRefresh` + the indicator row in SidebarContent, `data-slot="pull-to-refresh"`). Touch laws on every mobile-reachable control: 44px minimum hit area — visually small controls keep their size and extend the tap area with the `touch-hit` utility (`src/index.css`, pointer-coarse only, requires `relative`); no action gated behind hover (fence hover reveals with `md:` or `touch:opacity-100`, never `sm:`); text inputs 16px below md (`text-base md:text-sm`) so iOS Safari never zooms on focus; bottom chrome pads `env(safe-area-inset-bottom)`; full-height mobile surfaces use `dvh`, never `vh`/`h-screen`.

## Tokens

All color tokens are HSL triplets consumed as `hsl(var(--token))`, defined in `src/index.css` (`:root` = light, `.dark` = dark) and mapped to Tailwind utilities in `tailwind.config.js`.

### Typography

Self-hosted Schibsted Grotesk Variable (weights 400–900, normal + italic) via `@fontsource-variable/schibsted-grotesk`, imported at the top of `src/index.css`. No CDN font dependencies.

- `--font-ui` — UI chrome. Tailwind `font-sans` (the body default).
- `--font-message` — chat message content. Tailwind `font-serif` (legacy utility name kept so existing call sites resolve to the message cut; do not add real serifs).

Both currently point at the same family; keep them separate so the cuts can diverge.

### Radius

- `--radius: 0.5rem` (8px) — the one app-wide corner radius token. Tailwind `rounded-lg` = token, `rounded-md` = token − 2px, `rounded-sm` = token − 4px. Do not use `rounded-xl`/`rounded-2xl` on standard surfaces; desktop surfaces that carried hardcoded 12px radii were migrated to `rounded-lg`.
- Never apply asymmetric per-corner radii (`rounded-br-*` etc.) in the chat view. `rounded-full` is reserved for genuine circles (dots, spinners, radios, avatars, circular icon-only buttons); no pill/capsule shapes anywhere (ui8 phase 4) — every chip, badge, counter, status indicator, and thin bar track sits on the box-radius family (`rounded-md` for small chips, `rounded-sm` for tiny counters and bar tracks, `rounded-lg` for larger surfaces).

### Colors (semantic, light/dark via `.dark`, theme via `data-theme`)

`--background` / `--foreground`, `--card`, `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring` — each with a `-foreground` pair where applicable. Nav-specific glass tokens (`--nav-glass-*`, `--nav-tab-*`, `--nav-input-*`) also live in `src/index.css`.

Named themes (ui8 phase 4): a theme is a full color-token set with light and dark variants, selected in Settings → Appearance (and the mobile quick-settings flyout), persisted in localStorage `color-theme`, applied as `data-theme` on `<html>` by `ThemeContext`. The catalog lives in `src/shared/themes.ts`; the base `:root`/`.dark` pair in `src/index.css` IS the default **Steel Blue** theme, and each additional theme (**Graphite**, **Ink**, **Moss**, **Copper**, **Dune**) is a `[data-theme='<id>']:not(.dark)` / `[data-theme='<id>'].dark` override block covering every color token plus `--beam-ink` and the nav tokens. Only color tokens vary per theme — radius, type, and spacing are shared. The browser `theme-color` meta follows the active theme's computed `--background`. New themes get a full token pair in both files; never a partial override.

- Accent: silver-leaning silver-blue. Light `--primary: 211 20% 45%` (`--primary-foreground` white); dark `--primary: 211 22% 64%` (`--primary-foreground` near-black, the lighter accent needs dark type). `--ring` and the nav glow/focus tokens carry the same hue per theme. Every accent use (send button, links, active states, selection ticks, progress ring fill, focus rings) goes through `primary`/`ring` utilities — never hardcode blue or orange Tailwind palette classes. Warning states use the amber family; nothing uses the orange family.
- User message bubble: `bg-secondary text-secondary-foreground` (lighter gray bubble on the darker background in dark mode, white text). No blue bubble, no avatar circle.
- Secondary/metadata text: `text-muted-foreground`.
- Icons are monochromatic app-wide in every theme (ui8 phase 4): control, menu, header, and empty-state glyphs render in `currentColor` / `text-muted-foreground` / `text-foreground` — never a decorative, identity, or destructive-intent color (no red trash cans, no per-language file-icon colors, no colored provider logos; `ClaudeLogo` is `fill-foreground`/`fill-background`). Destructive intent conveys through copy and confirm dialogs. Data inks stay data: diff add/remove, chart/legend colors, success/failure state glyphs, live status dots, task priority encoding, attention amber, recording red, terminal green.

### Shadow & spacing

- Bubbles and inline chat elements: flat, no shadow beyond what the component already carries.
- Popovers/menus: `border border-border bg-popover shadow-lg` with `rounded-md`/`rounded-lg`.
- Mobile safe-area and nav spacing variables (`--mobile-nav-*`, `--safe-area-inset-*`) are defined in `src/index.css`; use them, don't hardcode offsets.

## Reusable-element inventory

Shared primitives (shadcn-style, use these first): `src/shared/view/ui/`

(`Queue.tsx` was retired; task lists render through the beUI `TodoList`.) `ActionMenu` items take an optional `trailing` node — right-aligned `text-[10px] tabular-nums text-muted-foreground` metadata on the label line (the worker run switcher's relative date).

Passing `status` opts into the animated state treatment: rolling icon/text swaps on status change, spinning loader with pulse for in-progress states; suppressed under prefers-reduced-motion. Wired on the worker/planner header state chips and the tool-row `ToolStatusBadge` — never invent status badges elsewhere.

Chat view: `src/components/chat/view/`
- `ChatInterface.tsx` — top-level chat screen.
- `subcomponents/MessageComponent.tsx` — one message (user bubble, assistant/tool/error layouts).
- `subcomponents/MessageCopyControl.tsx` — single copy button, always copies plain text.
- `subcomponents/MessageSpeakControl.tsx` — TTS button.
- `subcomponents/Markdown.tsx` — markdown renderer (`prose prose-sm font-serif dark:prose-invert` pattern). Fenced code renders in the beUI code-block chrome: `rounded-lg bg-muted/80` panel, `h-10` header (file icon, uppercase language tag, circular hover copy button with check swap), `border-t border-foreground/[0.06]` code viewport capped at 280px with internal scroll.
- `subcomponents/ChatComposer.tsx` — input composer (unified single box: textarea on top, one control row below; plus/attach left, model selector + send right; no hint text, no permission selector — sessions are hardwired to skip-permissions). At rest the box is exactly one text line tall (`rows={1}` textarea) and autogrows upward as content wraps. Focus state is a quiet gray (`focus-within:border-muted-foreground/40` + `ring-muted-foreground/20`), not the accent. The slash-commands icon is a custom single diagonal stroke matching the plus icon's arm length and stroke width; a Handoff button (document icon, `FileTextIcon`, all form factors, planner project chats only — hidden in the worker pane and standalone/scratch chats) sits immediately right of it and fires the `/handoff` user command through `/api/commands/execute`. A character counter (`data-slot="char-counter"`, `text-[10px] tabular-nums text-muted-foreground`, digits rolling through `NumberTicker`) sits left of the model pill whenever the input is non-empty. A text paste over 2,000 characters collapses into a "Pasted text.txt" attachment chip (Claude-desktop style) instead of flooding the textarea, and is delivered through the existing attachment path (`/api/assets/files` upload + `<files_input>` reference). Composer drafts are server-persisted per session (ui8 phase 2): text and uploaded-attachment descriptors save on a 500ms debounce to `/api/drafts/<key>` (key = session id, or `project:<projectId>` for the new-chat box), restore when the session opens anywhere, and sync live across devices through the `draft_updated` websocket broadcast; attachments upload the moment they are attached and their chips render from descriptors, so a draft's attachments survive reloads and device switches. `ComposerModelMenu.tsx` — Claude.ai-style model switcher (pill: friendly name + effort + chevron; card + Effort and More models submenus; friendly labels only, wire values unchanged). More models hides the selected model (it renders as the checked card above) and splits the rest into current and legacy groups separated by a `ComposerMenuSeparator`, driven by the `group` field on the one plain catalog array in `server/modules/providers/list/claude/claude-models.provider.ts` (id, friendly name, tagline, group, in display order), `CommandMenu.tsx` — composer menus (portal + `bg-popover` pattern).
- `src/shared/view/beui/` — the vendored beUI kit (beui.dev), rethemed to this app's tokens: `MessageScroller` (follow-output transcript scroller — ResizeObserver keeps the live edge pinned, smooth-scrolling as streamed content grows), `StreamingResponse`/`useStreamedReveal` (live-turn reveal at ~126 chars/s), `BrailleLoader` (horizontal ASCII Braille loader), `AgentDisclosure` (transform-only collapsible reveal), `SwapText` (roll label swap), `textShimmer` (the one text-shimmer treatment for in-progress labels), `ease.ts` (the motion springs/easings — use these, never ad-hoc curves). Phase-4 additions: `ActionSwapIcon` (blur icon swap for state-changing controls), `BeuiSwitch`, `BeuiTabs` (pill/underline/segment tabs with the `TABS_INDICATOR_SPRING` layoutId indicator), `BeuiSelect` (bouncy unfold select), `BeuiRadio` (`RadioGroup`/`RadioDot` gliding indicator), `NumberTicker` (rolling digit columns for live counts), `Loader` (dot-matrix + dither loading marks), `TodoList`, `Citations` + `useFavicon`, `ToolApproval`. Phase-5 additions: `BorderBeam`/`BorderBeamOverlay` + `useBeamPresence` (the activity shimmer — see App chrome), `MarqueeLabel` (overflow-aware row label from the ai-sidebar), `BounceIndicator` (bounce-sidebar active dot on a curved spring path). New collapsibles, controls, and loaders on the chat surface extend this kit.
- Control laws from the phase-4 adoption: any control whose icon changes with state renders it through `ActionSwapIcon`, never a hard cut (composer submit send/stop/queue, voice mic). Values that change while the user watches (composer character counter, activity-indicator elapsed time, context-popover header value) render through `NumberTicker` with a `format` callback — digits roll in place, unit glyphs (`k`, `M`, `%`, `m`, `s`) render as plain text, so the displayed string is byte-identical to the static version. Every true loading overlay or pinned loading state (chat transcript, sidebar, code/PRD editor overlays, shell connection overlay, git panel views) uses the beUI `Loader` (`dot-matrix` app-wide, `dither` on shell/terminal surfaces); inline button spinners keep `Loader2`/spin. The composer model-switcher pill rolls its model/effort labels through `SwapText` on selection.
- `BeuiSwitch` is the one toggle: h-7 w-12 track `rounded-md`, h-5 w-5 thumb `rounded-sm` (box radius, not a pill), checked `bg-primary`, spring-driven thumb with press squish-stretch; optional `thumbContent` centers an icon in the thumb (DarkModeToggle's Moon/Sun). `SettingsToggle` and `DarkModeToggle` delegate to it.

Underline variant (h-px `bg-primary`) drives GitViewTabs; segment variant (`bg-primary` pill on the rounded-md step) drives MainContentTabSwitcher inside the old muted bar chrome; the Settings desktop sidebar reuses the same spring for its gliding `bg-accent` row highlight. The sidebar segmented control (`PillBar`) is untouched pending the phase-5 sidebar steal.

Trigger `rounded-lg border-input bg-card` with `ring` focus; panel on the popover spec; selected tick `text-primary`. Homes: Appearance tab selects, LanguageSelector.
- Radio: `BeuiRadio`'s `RadioDot` — ring-and-dot whose inner `bg-primary` dot glides between options via shared `layoutId`. AskUserQuestionPanel's single-select rows compose it with `SPRING_PRESS` tap feedback; multi-select rows keep the checkmark.

App chrome
- Sidebar identity & activity (phase 5, on the beUI ai-sidebar anatomy; selection redone in ui8 phase 3): desktop project and session rows are borderless `min-h-9 rounded-lg px-2` rows with NO filled hover or selected background — hover and selection are quiet ink shifts (`text-muted-foreground hover:text-foreground`, selected `text-foreground`), focus keeps the inset ring. The bounce dot is the one honest indicator of the open chat: a 6px `bg-primary` dot (`BounceIndicator`) arcs on a curved spring path to the open session's row (`data-bounce-key`, stamped on the desktop and mobile row variants and on Chats-feed rows; the indicator measures the visible variant and re-seats through resize + DOM-mutation observers — its observers attach in a passive effect because a child's layout effects run before the host container's ref exists). When the dot's destination row isn't rendered — the open chat's project is collapsed, or a project is open as a workspace row — the project row carries the static `data-slot="project-open-indicator"` dot (`bg-primary/70`, same seat). Project rows show the project icon tile, an overflow-aware `MarqueeLabel` (hover scrolls an overflowing name, fitting names never move; `flex-initial` so it hugs its text), the chat-count numeral inline at the title's end (`data-slot="project-session-count"`, never hover-revealed), hover-revealed actions, and a spring-rotated chevron. Session rows carry NO provider icon tile — just label, count badge, age, and the options menu. Session names are `text-[13px] leading-4` in BOTH the Projects tab and the Chats tab — never `text-sm`. The session block unfolds/folds with a 0.18s EASE_OUT height+opacity reveal, indented by depth padding (`md:pl-5`), no tree rule, with `space-y-1` breathing room and a margin under the New Session button. Project editing is the `ProjectEditDialog` (shared Dialog chrome, labeled Title / Path / Planner memory name fields; the path is editable — the rename API re-points the project row and its sessions).
- Project icons: `iconDataUrl` on the project payload (repo-root `app-icon.svg` → `icon.svg` → `icon.png` convention, else the bundled SpotOn icon from `public/project-icons/`, else null). `ProjectIcon` renders it at `h-4 w-4 rounded-[3px]` in the ai-sidebar `size-5` grid tile; the default is lucide Folder/FolderOpen — the beUI default, never a custom glyph.
- Activity shimmer: the vendored `BorderBeam`/`BorderBeamOverlay` (`src/shared/view/beui/BorderBeam.tsx`, npm `border-beam` engine) — rotate mode, mono colorway, ink `--beam-ink` (light `211 10% 42%`, dark `211 16% 78%`; a neutral silver, never the accent), ambient strength 0.4. A mid-turn chat row carries the beam (it replaced the old green pulse dot); a project row carries it while any of its sessions runs AND the project is collapsed — expanding hands the shimmer to the chat rows. Mount beams through `useBeamPresence` so every appearance/disappearance is the engine's fade, never a hard cut.
- Active-session counters (ui8 phase 3): one full-width two-column bar (`data-slot="activity-counter-bar"`) pinned to the sidebar bottom above Settings — planner left (Compass + primary), worker right (Hammer + emerald), rectangular on the app radius (`rounded-lg border`, no pill). Counts roll through `NumberTicker`; a column breathes (`animate-counter-breathe`, opacity/filter swell, reduced-motion off) while its count is nonzero; the whole bar hides when both are zero. The collapsed rail shows the same pair as `RailCounter` (icon left, number right, same breathing, same hide-at-zero) above the rail's Settings button. Planner = origin `planner` or null, worker = `direct`/`dispatch`/`external` — the same split as the pane headers.
- Sidebar: `src/components/sidebar/`; main layout: `src/components/main-content/`, `src/components/app/`. The main chat pane and the worker pane each carry the same slim header bar (`border-b border-border/60 bg-muted/30 px-3 py-1.5`, muted icon + `text-xs font-medium` label): "Planner" with the open session's title in `MainContent.tsx` (label follows the open session's origin — a worker-origin session shows "Worker" with the Hammer icon), "Worker" with the run switcher in `WorkerPane.tsx`. Both headers carry fail-safe chips through the shared `Badge` (`status="danger"`, `size="sm"` — rounded-md rectangle, destructive colorway): "disconnected" while the websocket is down, "stream mismatch" if the rendered transcript diverges from the claimed session for over 2s. On desktop each header ends in an `h-6 w-6` ghost X that collapses its pane into a slim `w-6` rail with a rotated `text-[10px] font-medium tracking-wide` label (planner leftward, worker rightward), persisted per pane in localStorage (`planner-pane-open`, `worker-pane-open`); the two headers measure the same height — the Tooltip wrapper is `inline-flex` so a wrapped button never adds phantom line-box height. New pane-level headers extend this bar, never a parallel style. `SidebarHeader.tsx` is one shared header (equal-width segmented control in the top button bar + ghost icon cluster + search; mobile adds the Running segment and create-project button, desktop the collapse button); `SidebarFooter.tsx` is the single bottom-pinned Settings row on both form factors.
- Multi-project workspace (phase 7): `WorkspaceView` (`src/components/app/workspace/`) wraps the desktop main surface. One open project renders MainContent untouched; opening a second (sidebar project-row hover toggle, Rows2 icon, `text-primary` while open) stacks one `WorkspaceRow` per project — planner pane + worker pane, both on the standard pane-header bar. The workspace planner header extends the bar with a leading drag grip, project icon + name (truncating), and trailing New-planner-session / layout-toggle / close-row `h-6 w-6` ghost buttons; the label stays origin-aware (Hammer + "Worker" for worker-origin sessions). Rows mode shares one planner/worker split fraction so planners align over planners; columns mode (toggle) lays the pairs side by side with per-project splits. Dividers are slim `bg-border/60 hover:bg-primary` bars (the editor-sidebar resize pattern on tokens); dragging a grip shows a 2px `bg-primary` snap guide at the nearest drop boundary. Order, mode, split, and weights persist in localStorage `workspace-layout-v1`. The URL-driven selection is always the primary row; extra rows manage their own planner sessions (WorkerPane pattern) and never touch the app URL or the global selected session.
- Settings: `src/components/settings/`; quick settings: `src/components/quick-settings-panel/` (mobile-only edge flyout; desktop gets these settings in the Settings page's Appearance tab).

Global CSS (scrollbars, transitions, chat containment classes, placeholder colors): `src/index.css`. Scrollbars are one app-wide treatment (ui8 phase 3): thin and trackless — 4px webkit width, transparent track, `muted-foreground/0.35` thumb on 2px radius, `scrollbar-width: thin` everywhere; never style a per-surface scrollbar.
