# Composer

- `subcomponents/ChatComposer.tsx` — input composer on the claude.ai layout (ui15 job 2). Inside the enclosure, top to bottom: the attachment strip, then a full-width text row, then the bottom controls row (`data-slot="composer-controls-row"`, `flex items-center gap-1 px-2 pb-1.5 pt-0.5`, `h-7 w-7` controls): plus (the drawer-menu trigger since ui13 job 12) at the left, then a flex spacer, then the right group in order — the Handoff button (`data-slot="composer-handoff"`, `FileTextIcon`, planner project chats only; back out of the plus menu, Willem's call), the prompt-history toggle (`data-slot="composer-history-toggle"`, `History` icon, `aria-pressed` + `bg-accent/60` while open; both carry the sanctioned icon-only tooltips), the model switcher, and send. The textarea (`px-3 pb-1 pt-2` at `13px/20px` on desktop — phones keep `text-base` for the iOS zoom rule) spans the enclosure's full width above the controls with no flanking button columns and no dead-space gutters. Slim secondary row (`data-slot="composer-secondary-row"`, ui11 phase 5 / ui12 phase 2: a sibling rendered BELOW the bordered enclosure, never a descendant of it — `mt-1`, NO horizontal padding, `h-7 w-7` buttons: the left cluster's edge and the context ring's right edge sit flush with the enclosure's borders): character counter + voice left, the counter first so its box sits flush with the enclosure's left edge; the context ring alone at the right (the model switcher moved up into the controls row in ui15 job 2). Attachment previews (ui11 phase 5) sit inline above the text inside the enclosure (`data-slot="prompt-input-header"`, `flex gap-2 overflow-x-auto` — one non-wrapping row that scrolls horizontally when the chips overflow, ui15 job 2; no gray container): each preview is an 80px square carrying the enclosure's own border treatment (`rounded-lg border border-border/50 bg-background/80 shadow-sm`) — images `object-contain` (never cropped), non-image files an icon + truncated name + size square, pasted text the PASTED chip; preview buttons use `focus-visible` rings only, so a mouse click opening a preview never flashes a stroke (ui12 phase 2, also applied to transcript image thumbnails). No hint text, no permission selector — sessions are hardwired to skip-permissions. Focus state is a quiet gray, not the accent, and lives on one overlay (ui13 job 12): `data-slot="prompt-input-focus-glow"` in `PromptInput.tsx` carries the whole focused treatment (`border-muted-foreground/40` + `ring-muted-foreground/20` + `shadow-md`) as a sibling outside the overflow-hidden form (so the outward glow never clips) and fades through opacity alone (`.prompt-input-focus-glow` in `src/index.css`, 0.2s EASE_IN_OUT, driven by the shell's `:focus-within`) — a single-channel fade is monotonic in both directions, where the old border/ring/shadow-list crossfade on the form was not. `ComposerPlusMenu.tsx` (ui13 job 12) — the plus button opens a drawer menu of stacked rows (`data-slot="composer-plus-menu"`, the shared popover surface + `ComposerMenuItem` rows at `py-2.5` with `touch-hit`), top to bottom: Upload a file (opens the attachment picker) and Slash commands (inserts the command palette; its icon stays the custom single diagonal stroke matching the plus icon's arm length and stroke width). Handoff left the menu in ui15 job 2 for its own controls-row button (still planner project chats only — hidden in the worker pane and standalone/scratch chats; fires the `/handoff` user command through `/api/commands/execute`). It opens with the standard popout grow and closes on selection, outside press, or Escape through a ramped exit — `popout-exit-up` in `src/index.css`, the enter wipe reversed on EASE_IN_OUT, played before unmount. The character counter (`data-slot="char-counter"`, `font-mono text-[10px] tabular-nums text-muted-foreground` — the shared number style, ui12 job 9) is plain tabular text with en-US grouping, always rendered, a static `0` before typing (ui14 job 6: it left `NumberTicker` because the ticker's per-column layers snapped identical digits to different subpixel boxes at some zooms; one text node gives identical glyphs identical boxes at every DPR, and a counter does not need a roll). Clear-with-undo (ui15 job 2): the counter is a button — hovering (or focusing) it crossfades the number into an X (`.counter-swap`, 0.2s EASE_IN_OUT; on touch the count stays visible and a tap clears directly), clicking clears the prompt and every attachment and swaps the counter slot for the `data-slot="composer-undo-clear"` "Undo?" affordance whose underline depletes over the 4s window (`.undo-deplete`, EASE_IN_OUT, static under reduced motion); Undo restores the exact text and attachments, letting it deplete finalizes the clear, and switching composer surfaces drops the window. The window constant is `CLEAR_UNDO_WINDOW_MS` in `useChatComposerState.ts`. A text paste over 2,000 characters collapses into a pasted-text attachment (delivered through the existing attachment path: `/api/assets/files` upload + `<files_input>` reference) whose chip is the Claude.ai-style square PASTED card (`data-slot="pasted-text-chip"` in `ComposerAttachment.tsx`: 80px square, miniature `text-[6px]` first-sentences preview, gradient-faded PASTED label bottom-left; clicking opens `data-slot="pasted-text-viewer"`, a shared-Dialog full-text viewer). In the composer the viewer is an editor (ui14 job 6, `data-editable="true"`): a plain `textarea` (`data-slot="pasted-text-editor"`, the viewer's own text style) with Cancel (ghost) and Save (`Button size="sm"`) in a bordered footer; Save and every close path (X, Escape, outside press) write the text back — the edited text becomes a fresh File under the same name and re-uploads through the normal attachment path, so the chip preview, the server-persisted draft, and the send all carry the edit — while Cancel restores the original. A sent bubble's viewer stays read-only and says so with a small `Read only` caption beside the name. Composer drafts are server-persisted per session (ui8 phase 2): text and uploaded-attachment descriptors save on a 500ms debounce to `/api/drafts/<key>` (key = session id, or `project:<projectId>` for the new-chat box), restore when the session opens anywhere, and sync live across devices through the `draft_updated` websocket broadcast; attachments upload the moment they are attached and their chips render from descriptors, so a draft's attachments survive reloads and device switches. `ComposerModelMenu.tsx` — Claude.ai-style model switcher (floating `h-7` trigger in the controls row: the current model's provider mark at icon size (`h-3.5 w-3.5`) + friendly name + effort + chevron in `text-muted-foreground`, effort visible on every form factor including phones (ui13 job 12), no background fill or border — the send button stays the input row's only blocky element; card + Effort and More models submenus; friendly labels only, wire values unchanged). More models lists both engines in use (codex job 4): the Claude group then the OpenAI group, each headed by its provider mark (`data-slot="model-group-mark"`, `ProviderMark` from `src/components/llm-provider-logo/ProviderMark.tsx` — the Claude starburst and the OpenAI knot in `currentColor` at the heading's muted ink, so every theme holds; the marks appear nowhere else in the composer). The selected model hides from its group (it renders as the checked card above); the Claude group splits current and legacy models with a `ComposerMenuSeparator`, driven by the `group` field on the one plain catalog array in `server/modules/providers/list/claude/claude-models.provider.ts` (id, friendly name, tagline, group, in display order); the Codex catalog (`codex-models.provider.ts`) is exactly Sol, Terra and Luna at low/medium/high/extra, high default. Picking a model from the other group switches the composer to that provider: with no chat open the next New Session boots on it; with a chat open (a chat never changes engine mid-conversation) the pick starts a new session on that engine through the pane's own New Session action (`onStartNewSession`: the app-level New Session for the primary planner surface, the row's for extra rows, `handleNewWorkerSession` for the worker pane), which boots `/planner` or `/worker` there. Effort labels are shared across providers (`EFFORT_LABELS`: Low, Medium, High, Extra, Max), `CommandMenu.tsx` — composer menus (portal + `bg-popover` pattern).
- Context window truth (pauseresume job 2): `TokenUsageSummary` is provider-specific. Claude keeps the SDK category breakdown and usable-window treatment unchanged. Codex reads only the newest rollout `token_count.info.last_token_usage` against `model_context_window`; cumulative `total_token_usage` is never a context source. Its expanded popover lists exactly Input from cache, Fresh input, Output, Reasoning, and Context window using the rollout values (fresh input is total input less cached input), and says “No reading yet” before the first token event. The existing sessions filesystem watcher pushes `session_token_usage` over the shared WebSocket on Codex rollout changes, scoped by app session id; the client does not poll.
- Queued-message stack (ui11 phase 1 single card; a stack since ui15 job 2): queueing while messages are already queued appends another card — the cards render in delivery order above the composer (`data-slot="queued-card-shell"` wrapping `QueuedMessageCard`), pushing the transcript up through the `--composer-height` var. Each card edits (pulls its text and attachment descriptors back into the composer) and deletes independently. Storage is the server `queued_messages` table (one row per message, client-generated `id`, `position` append order); every write/claim broadcasts `queued_message_updated` carrying the session's whole ordered stack. Delivery preserves order: the Claude runtime steers the HEAD into a running turn at tool-result boundaries (ui11 phase 2), and end-of-turn flush plus app-level auto-send always claim-pop the head — later messages flush at the following turn ends. Sync clear law (ui15 job 2): the steer's echoed user bubble carries `queuedMessageId`, and the client drops the matching card in that same event (`settleQueuedMessageDelivered`), so card clear and bubble land in one commit — never two round trips; a removed card ramps closed via the shell's grid-rows collapse (0.25s EASE_IN_OUT), never a hard unmount.
- Pane-wide file drop (ui15 job 2): the whole chat pane (`data-slot="chat-pane"`, the `paneRef` div in `ChatInterface`) is the dropzone — dragging a file over the planner or worker pane shows the subtle themed wash (`data-slot="pane-drop-highlight"`: inset dashed `border-primary/40` + `bg-primary/[0.06]` + a small "Drop to attach" chip) and dropping attaches to that pane's composer exactly as a prompt-bar drop; per pane in multi-pane layouts. Project-row drags never trigger it (react-dropzone only reacts to real files).
- Prompt history panel (ui15 job 2, `PromptHistoryPanel.tsx`, `data-slot="prompt-history-panel"`): the controls-row history toggle expands the prompt bar area into a panel one third of the pane tall (measured from `data-slot="chat-pane"`, min 180px) via a grid-rows ramp (0.3s EASE_IN_OUT both ways), listing the user's past prompts newest first — this session's and the project's recent conversations, served by `GET /api/prompt-history` (`server/modules/prompt-history/`, which scans the Claude transcript JSONLs of the current session plus up to 10 recent project sessions for real typed prompts — commands, meta rows, and tool results excluded — and parses attachment descriptors back out of the `<files_input>`/`<images_input>` tags). Rows: truncated prompt, paperclip count, time, chevron; expanding shows the full text and downloadable attachment chips (`/api/assets/files/<name>`, the files live on the mini); the hover-revealed Use action (`data-slot="prompt-history-use"`, `touch:opacity-100`) loads the prompt and its descriptors into the composer and closes the panel. Escape closes; fetches show `Skeleton` rows.
- Spellcheck law (ui15 job 2): no browser spell/grammar underline anywhere — `PromptInputTextarea` and the shared `Input` default `spellCheck={false}` + `autoCorrect="off"` (the composer textarea keeps `autoCapitalize="sentences"` for phone dictation), and every raw `<input>`/`<textarea>` (message edit, pasted-text editor, commit boxes, renames, searches, auth fields, cmdk) sets the same explicitly. New text fields must not ship with spellcheck default-on.
