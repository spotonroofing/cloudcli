# Transcript rows

Chat view: `src/components/chat/view/`
- `ChatInterface.tsx` — top-level chat screen.
- `subcomponents/MessageComponent.tsx` — one message (user bubble, assistant/tool/error layouts).
- Compact command bubble (ui11 phase 3, `data-slot="command-bubble"` in MessageComponent): any slash command sent from the composer renders inside the standard user bubble shell as its mono command name (`font-mono text-sm`) plus the command file's one-line description (`text-xs text-muted-foreground`, truncating); the expanded command text never shows by default — the whole header line toggles it (ui13 job 13, Bash-row expand behavior), with a spring-rotated `ChevronDown` (`size-3.5` in a `size-4` slot, `touch-hit`) as the affordance, revealing a standard `rounded-lg bg-muted/80` mono viewport capped at 280px via `AgentDisclosure`. Commands travel as the Claude-style `<command-message>/<command-name>/<command-args>` wrapper plus body (`src/components/chat/utils/commandMessage.ts`, server twin `server/shared/command-message.ts`), so the bubble renders identically live and on reload. Command bubbles keep the copy meta but never the edit pencil, rerun, or a timestamp.
- `subcomponents/MessageCopyControl.tsx` — single copy button, always copies plain text.
- Edit-and-resend versioning (ui9 B3; inline editor ui11 phase 13): a pencil sits left of the copy control on text-only user turns (same hover-fade meta-row treatment); clicking turns that bubble into the inline transcript editor (`data-slot="message-edit"` in MessageComponent, claude.ai-style): an auto-growing textarea in a `bg-secondary` box wearing the app focus border (`border-muted-foreground/40 ring-1 ring-muted-foreground/20 shadow-md`), caret at the end, `text-base` on phones / `sm:text-sm` on desktop, with a right-aligned Info icon + ghost Cancel + primary Save row below (`touch-hit` on both buttons). Save resends through the versioning (unchanged Save is a no-op close), Cancel and Escape restore the bubble, Cmd/Ctrl+Enter saves, one editor open at a time. The prompt bar is never touched — no composer edit indicator exists anymore. A resent exchange renders `subcomponents/MessageVersionNavigator.tsx` (`data-slot="message-version-nav"`) under the visible response: always-visible left chevron / `n / m` tabular-nums / right chevron in `text-[11px] text-muted-foreground`, `touch-hit` on both buttons, arrows disable at the ends. Versions live in CloudCLI's `message_versions` table; the Claude transcript is never rewritten (hidden, never deleted).
- `subcomponents/MessageSpeakControl.tsx` — TTS button.
- `subcomponents/Markdown.tsx` — markdown renderer (`prose prose-sm font-serif dark:prose-invert` pattern). Fenced code renders in the beUI code-block chrome: `rounded-lg bg-muted/80` panel, `h-10` header (file icon, uppercase language tag, circular hover copy button with check swap), `border-t border-foreground/[0.06]` code viewport capped at 280px with internal scroll. Markdown images (ui13 job 6) render through `MarkdownInlineImage.tsx`: `![caption](path)` whose path is a file inside the pane's project workspace (relative to the project root, or absolute inside it) blob-fetches through the authenticated `/api/file-tree/.../files/content` route (which 403s anything outside the project) and renders as an inline image card — composer-thumbnail border language (`rounded-lg border border-border/50 bg-background/80 shadow-sm`), `max-h-80 object-contain` (never cropped), click opens the zoomable `ImageLightbox`. URLs with a scheme, paths outside the workspace, and missing files never render an image — they fall back to a muted `ImageOff` + mono-path line. The pane's project comes from `ChatProjectContext` (provided by `ChatInterface`), never threaded props. SVG and the common raster formats are covered; the model-side marker contract is documented in CLAUDE.md.
- `subcomponents/ImageLightbox.tsx` — the one fullscreen image overlay (ui13 job 6), shared by composer attachment chips, transcript image thumbnails, and inline markdown images. Dark scrim (`z-[100] bg-black/80 backdrop-blur-sm`), close on X / Escape / backdrop click (a pointer-move guard so ending a pan over the backdrop never closes). Zoom everywhere: wheel and double-click-toggle zoom with drag-pan on desktop, pinch-to-zoom and pan on touch via `react-zoom-pan-pinch` (the transform wrapper takes `touch-action: none` so the browser never steals the gesture), 1x–8x. Bottom-center control pill (`bg-white/10` circle buttons): zoom out, the live scale percentage in `tabular-nums` (click = reset), zoom in.
- Tool-permission prompts: `PermissionRequestsBanner` renders pending requests through the vendored beUI tool-approval card (`ToolApproval.tsx`, `data-slot="tool-approval"`): a `rounded-lg border-border/60 bg-muted/20` card with a shield tile, "Allow this tool to run?" title over the mono tool name, an amber "Approval required" chip (rounded-md), the allow-rule code chip, and a "View tool input" reveal via `AgentDisclosure` into the standard `rounded-lg bg-muted/80` mono viewport. Action row: Allow once solid, Allow & remember outlined, Deny ghost, with `SPRING_PRESS` tap feedback. AskUserQuestion routes to `AskUserQuestionPanel` (`data-slot="ask-user-question"`), merged with the beautifului Approval Card in ui9 B2: `rounded-lg border-border bg-card` shell, kicker + header chip, quiet option rows with kbd hints (1–9, 0), `RadioDot` glide for single-select / `bg-primary` check square for multi, inline free-text "Other", and a footer with chevrons + ring-dot pager (multi-question) and a forward arrow-up button that advances and sends on the last — answers never auto-send; the X skip control carries the one `Tooltip` (its purpose is not self-evident) — the pager chevrons, ring dots, and forward button rely on their aria-labels per the ui13 tooltip law. ExitPlanMode stays with PlanDisplay.
- Task lists: `TodoList` (`data-slot="todo-list"`) — a bordered `rounded-lg` card with an `h-11` header (ListTodo icon that spring-swaps to an emerald check when all items complete, rolling `completed/total` count via `SwapText`, spring-rotated chevron) over an `AgentDisclosure` viewport capped at 248px. Rows carry animated SVG status circles: dashed pending, spinning arc in-progress, drawn check + strike-through completed. All TodoWrite/TodoRead tool rows render through it.
- Citations: `Citations` (`data-slot="citations"`) — a quiet "Sources" toggle revealing favicon rows (site favicon via `useFavicon` with a Globe fallback, title, domain, index chip) through `AgentDisclosure`. An assistant message whose markdown contains external http(s) links gets exactly one strip after the body, deduped by URL (`extractExternalLinks` in `chatFormatting.ts`); user messages, tool rows, and link-free messages never show it; inline prose links are untouched.
- `subcomponents/ActivityIndicator.tsx` — response-in-progress indicator (beautifului Loading State, ui9 B2): `PixelLoader` left of a shimmering status word plus a decisecond elapsed counter in mono tabular figures (`NumberTicker`). The word and its bound loader animation rotate together every ~6.5s of activity (Thinking→drive, Working→dots, Churning→orbit); server status text overrides the word. Transcript thinking blocks and Task subagent turns render through the beUI `Thinking` trace (reasoning / steps modes; a subagent's result excerpt lives in the trace footer, so the separate Task result row is suppressed); WebSearch/WebFetch turns render as the Research tool row (see the tool-row entry, ui12 job 10), no longer through the trace's search mode; consecutive same-tool groups keep the ToolGroupContainer anatomy with the coding-mode treatment — the header label shimmers while any tool in the run awaits its result. Live streamed turns wrap words in `.bui-stream-word` blur-in spans (`streamWords` on `Markdown`, skipped inside code/KaTeX) with a caret pseudo-element on the last block (`bui-stream-caret-host`). The indicator covers BOTH panes honestly (ui13 job 13): externally-driven dispatched runs merge into the running-sessions poll (`listActiveDispatchRuns` in the watchdog → `/api/providers/sessions/running`, `canInterrupt` false), so a worker session shows the same live indicator and timer during a dispatched run instead of a silent gap; reload settles thinking into the collapsed "Thought for a few seconds" trace.
- Message rows: new live rows enter with the beUI message pop-up spring (`MESSAGE_POP_UP`, rise-and-scale from the bottom edge); loaded history renders statically. Action-button law (ui13 job 13, one consistent rule in both panes): user messages carry copy and rerun (rerun resends that row's own prompt through the composer submit path; text rows also keep the edit pencil, command bubbles and attachment-only turns get no rerun or pencil); the turn's FINAL assistant text — the last plain assistant message before the next user turn or the transcript tail (`turnFinalMessages` in ChatMessagesPane) — carries copy, speak, and the timestamp; intermediate assistant texts, thinking traces, error rows, and every tool row carry NO copy, rerun, or timestamp; assistant messages never get rerun. All of it follows ONE reveal rule (ui11 phase 4, `META_REVEAL_CLASS` in MessageComponent): `opacity-0 group-hover:opacity-100 touch:opacity-100` — hover-revealed on fine pointers, always visible on coarse; never the old `md:` width fence. The speak control stays visible mid-playback. User-message meta sits below the bubble, outside it. A pasted-text attachment on a sent user bubble renders the composer's own PASTED chip and viewer (`PastedTextAttachment.tsx`, shared with `ComposerAttachment`), never a generic file card.
- `subcomponents/ChatMessagesPane.tsx` — scroll container (wraps the beUI `MessageScroller`). The scrollbar tells the truth (ui12 phase 3): the scroll viewport spans the full pane height to the viewport bottom, and the composer floats over it (`ChatInterface` renders the composer area `pointer-events-none absolute inset-x-0 bottom-0 z-10`; only the composer's centered `max-w-[54.25rem]` column takes pointer events and paints `bg-background`, so the right-gutter scrollbar stays visible and grabbable to the very bottom). The transcript clears the composer with a trailing spacer element inside the scroller content sized `calc(var(--composer-height) + 0.75rem)` (sm: `+1rem`) — a spacer, never padding, because the follow-output engine observes the content's content-box and padding growth would not re-pin the live edge; `--composer-height` is published on the pane root by a ResizeObserver on the composer area, so banners, queued cards, and a growing draft all keep the last message just above the enclosure with no whitespace band at full scroll. The transcript opens full and pinned (ui12 job 11): the initial tail page keeps fetching older pages until the container is scrollable or the transcript is exhausted (`resolveTranscriptFillAction` in `chat/utils/transcriptFill.ts`), each fill page re-pinning the newest message above the composer; paging is silent — no "Showing X of Y" banner, no load-all prompt, ever — older pages load automatically near the scroll top with a small `data-slot="older-page-skeleton"` skeleton holding the incoming page's space. Pinned-transcript law (ui13 job 15): a transcript at its live edge never leaves it without a wheel, touch, or key from the reader — background tail refreshes, streamed growth, and large landings all re-pin; `scripts/dev/check-pinned-transcript.mjs` is the regression check (drives the dev app over CDP, appends turns through the watcher path, then lands a large block mid-animation). `TokenUsageSummary.tsx` — circular context-usage progress ring; click opens the context-usage popover (a "Context window" header row `<used>k / <limit> (<percent>)` with a chevron that expands the SDK-reported per-category breakdown; no billing/plan section). Ring and popover divide the same `used` by the same `total` (the SDK-reported window, persisted per model id in `app_config` when a live turn observes it and served on session load; env `CONTEXT_WINDOW` is only the never-observed fallback). The popover opens to the left and upward on every form factor (ui13 job 12): its right edge aligns with the ring button's right edge (`useComposerMenuAnchor` default right-align; `maxWidth` shrinks it on narrow viewports), with the standard popout grow. The ring lives at the right end of the composer's slim secondary row (ui9 B6): `h-7 w-7` button, 16px svg, unused track `stroke-muted-foreground/30` — never the border token, which matches the `hover:bg-accent` fill and made the track vanish on hover. The ring is live in both panes (ui11 phase 11): runtime-driven runs stream `token_budget` status frames per assistant message, and externally-driven runs (dispatched chains, terminal sessions) refetch the persisted usage snapshot whenever the watcher-triggered tail refresh lands new rows — merged through `mergeTokenBudget` (`chat/utils/tokenBudget.ts`), which keeps the SDK-derived window and category breakdown under snapshots that carry only counters.
- `tools/ToolRenderer.tsx` (+ `tools/components/`) — tool input/result rendering. Every tool row (one-line, collapsible, Bash command row, grouped rows, subagent, error) carries the beUI tool-result treatment (beui.dev/components/agents/tool-result): a compact flush header row (muted icon or `$`, medium label, mono value in `text-muted-foreground`), a spring-rotated `ChevronDown` on the right when expandable, and content revealed through `AgentDisclosure` with a `pl-6` indent — expanded output/error bodies sit in a `rounded-lg bg-muted/80` viewport. Error rows use the rose status colorway (`text-rose-600 dark:text-rose-400`). No left rules, no per-category border colors. Tool-row status is leading-icon, never a chip (ui12 job 10, `ToolRowStatusIcon` in `tools/components/ToolRowStatus.tsx`): a running row leads with the shared ramped arc spinner (`animate-spinner-ramp`, `text-status-working`; the Bash row swaps its `$` slot for it), an errored row leads with a rose `CircleX` and carries its first error line in the description slot, a denied row an amber `CircleSlash`; completed rows carry no status mark. Web search/fetch turns render as the Research row (`ResearchDisplay.tsx`, `data-slot="research-row"`): "Research" label, the query (search) or domain (fetch) as the mono description, a source count at right, collapsed by default, expanding through `AgentDisclosure` to the beUI `CitationList` favicon rows (title + domain, new-tab links) built ONLY from the sources the tool result actually carried (`Links: [...]` block for search, the fetched URL for fetch) — nothing synthesized, so a session that never researched shows no Research row and an unexpandable one means the result carried no sources.
- Transcript row anatomy (ui13 job 13, the Bash row `BashCommandDisplay` is the reference; every row family — tool calls one-line and collapsible, Research, subagent/thinking/memory traces, interrupted markers, command bubbles — shares it): a `min-h-7 py-0.5 gap-2` header with `my-0.5` wrapper rhythm; a leading `grid size-4 place-items-center` icon slot, ALWAYS reserved (holds the `$`/tool glyph or `ToolRowStatusIcon` at `size-3.5`, empty otherwise) so the label column never shifts; a `text-xs font-medium text-foreground/90` label; a mono `text-[11px] text-muted-foreground/70` value/description (`text-xs text-foreground/90` for the Bash command itself); a trailing fixed `size-4` chevron slot (`ChevronDown size-3.5`, `SPRING_SWAP` rotate, empty on non-expandable rows) on one shared right-edge column; the WHOLE header row toggles expansion (a clickable title like Edit/Write stops propagation and opens the file), revealing through `AgentDisclosure` with a `pl-6` indent and no left rule. Tool rows carry NO copy buttons and NO timestamps (ui13 job 13 action law); their only trailing meta is a quiet count (`text-[10px] tabular-nums text-muted-foreground/70` — Bash line count, group `x{n}`, Research source count), never a chip. Consecutive tool rows pack tight: `.chat-message.tool-row + .chat-message.tool-row { margin-top: 0.25rem }` in `src/index.css` overrides the transcript's `space-y` gap so a run of tool calls reads as one block. One error row for the whole app (ui14 job 12): every session-level error (`type: 'error'` — provider errors, protocol errors, failed sends; anything that used to render as the red "!" block or a bare line) renders as `ToolErrorDisplay` on this same anatomy — leading rose `CircleX`, "Error" label, one-line truncated summary, trailing chevron, collapsed by default, expanding to the full text in the muted viewport — never a bespoke red box. Assistant prose is never swept in: limit messages and "No response requested." stay ordinary assistant text.
- Interrupted marker (ui11 phase 4, `data-slot="interrupted-marker"`): a turn killed mid-response (stop button, server restart, process death) shows a `Ban` icon (`size-3.5` in the standard `size-4` leading slot) + "Interrupted" row (`min-h-7 gap-2 text-[11px] text-muted-foreground/80`) at the cut point. Sources: the CLI's `[Request interrupted...]` user row normalizes into a marker (reload), a live abort appends one on the `complete {aborted}` event (consecutive markers collapse in conversion), and a dead tool-call tail with no active run renders one in `ChatMessagesPane`.
- Memory-updated marker (ui12 phase 7; thought-row anatomy + per-session attribution ui13 job 8; Bash/subagent attribution + change excerpt ui14 job 3, `data-slot="memory-updated-marker"` in MessageComponent): when a session writes planner memory (the spoton-worker repo's PROJECT.md/STATE.md/lessons/sessions, or `planner/_global/`) or native auto-memory, the transcript shows a "Memory updated" row rendered on the beUI `Thinking` trace (coding mode, `working=false`) so it shares the "Thought for a few seconds" meta-row family exactly — same `size-4` icon slot (a `size-3.5` `BookMarked` through the trace's `icon` override, settled `text-muted-foreground/60`), `text-xs font-medium` label, spring-rotated chevron, and grid-rows expand. Behind the expand, one `data-slot="memory-updated-file"` block per file: the file's trace row (the Thinking row anatomy), then `data-slot="memory-updated-diff"` — a compact plain-text excerpt of what actually changed in that file (`+`/`-` prefixed lines in the mono `text-[11px] text-muted-foreground/70` cut, at most six lines then "n more lines"), computed server-side from the file's before/after content (a line-set difference against the snapshot the memory watcher keeps), never a summary the model wrote; a file created after boot shows its lines as added (every existing memory file is snapshotted at boot). Detection is server-side and keyed per session (`server/modules/memory/`): the primary detector scans each changed Claude transcript's new tail for tool calls touching memory paths and attributes them to that exact session (worker writes land in the worker transcript, planner writes in the planner chat). Write/Edit/MultiEdit/NotebookEdit name their file and report on a non-error result; Bash calls (heredocs and appends, how workers actually write lessons and summaries) leave a soft claim on any memory path spelled out plus a time window on the session, and Agent/Task calls hold the window open until the subagent returns — the planner-repo chokidar watch, which sees the real change, reports it to the claimant. Writes no transcript claims (hand edits) defer 15s and then fall back to the running-run heuristic; writes within a 2.5s quiet window group into one row. Live it streams as a `memory_update` frame (through the run writer for seq/replay when a run is active); each burst persists as a `memory_updates` row (`files_json`, `diffs_json`) the client merges back in by timestamp on reload (`useMemoryUpdates` + `mergeMemoryUpdateRows`).
