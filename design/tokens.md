# Tokens and shared foundations

The app is Command Center (ui10 phase 2; mark redesigned ui11 phase 7). The mark is the command bracket — a caret held between two square brackets, the console frame around the prompt. Three round-capped, round-joined line paths in one stroke family, defined in `public/generate-icons.js`, which is the single source of truth: running it regenerates `public/mark.svg` (canonical, `stroke="currentColor"`), favicon.svg/png, the manifest icon PNGs, and `mark-{128,256,512}.png` (service-worker notifications + electron window icon). In React, render `CommandCenterMark` (`src/shared/view/CommandCenterMark.tsx`) — inline SVG, stroke inherits `currentColor`, so branded surfaces color it with a token class (`text-primary` on login and the auth loader) and it recolors with every theme. Never reintroduce a fixed-hex or filled logo; static renders (favicon, icon tiles) are the only baked colors and live only in generated files.
All color tokens are HSL triplets consumed as `hsl(var(--token))`, defined in `src/index.css` (`:root` = light, `.dark` = dark) and mapped to Tailwind utilities in `tailwind.config.js`.

### Typography

Self-hosted Schibsted Grotesk Variable (weights 400–900, normal + italic) via `@fontsource-variable/schibsted-grotesk`, imported at the top of `src/index.css`. No CDN font dependencies.

- `--font-ui` — UI chrome. Tailwind `font-sans` (the body default).
- `--font-message` — chat message content. Tailwind `font-serif` (legacy utility name kept so existing call sites resolve to the message cut; do not add real serifs).
- `--font-mono` — inline numbers, commands, code. Tailwind `font-mono`, resolving to the `'CloudCLI Mono'` @font-face in `src/index.css`: the local system monos wrapped with `ascent-override: 98% / descent-override: 26% / line-gap-override: 0%` — Schibsted's exact vertical metrics. Numbers sat off the line because the raw system monos carry smaller boxes (SF Mono 0.90/0.25), so flex-centering a mono span missed the sans baseline; with congruent metrics, centering IS baseline-sharing (ui11 phase 9). Never point `font-mono` at a raw system stack, and never per-site pixel-nudge a number — fix metrics here.

Both sans cuts currently point at the same family; keep them separate so the cuts can diverge.

- Figures are lining, everywhere (ui12 job 9): `body` carries `font-variant-numeric: lining-nums`, and a universal `--tw-numeric-figure: lining-nums` default keeps Tailwind's `tabular-nums` utility (which rebuilds `font-variant-numeric` from its composable vars) from dropping it — every tabular site computes `lining-nums tabular-nums`. Schibsted itself ships only lining figures (no `onum`/`lnum` in GSUB; digit tops differ only by ~1% optical overshoot); the rule is insurance for fallback families. Counters, timers, and token counts add `tabular-nums` (columns align); inline numbers ride the mono cut per `--font-mono` above. `NumberTicker` snaps its digit-box step to whole device pixels at mount (measured font-size × 1.1, rounded in device px) because its rolling columns are composited layers the browser pixel-snaps independently — a fractional step (1.1em at most sizes/zooms/DPRs) made digits ride visibly high or low relative to each other. The live turn counter (`ActivityIndicator`) formats elapsed time exactly per the beautifului mirror's loading-state: `12.3s` under a minute, `1m 50.3s` above — regular ASCII space between units, mono tabular digits. Two ui13 job 8 laws on top: inside `NumberTicker` a space glyph renders as NBSP (an inline-block whose only content is a collapsible space renders zero width — `1m 21s` displayed as `1m21s` while the accessible string still carried the space), and the elapsed timer passes `duration={0}` so its digits snap in place — the tenths digit updates every 100ms, faster than any roll can settle, so a rolling column there is perpetually mid-glyph and reads as digits at different heights; rolls stay on counters whose updates are sparse enough to settle (composer counter, token usage).

### Radius

- `--radius: 0.5rem` (8px) — the one app-wide corner radius token. Tailwind `rounded-lg` = token, `rounded-md` = token − 2px, `rounded-sm` = token − 4px. Do not use `rounded-xl`/`rounded-2xl` on standard surfaces; desktop surfaces that carried hardcoded 12px radii were migrated to `rounded-lg`.
- Never apply asymmetric per-corner radii (`rounded-br-*` etc.) in the chat view. `rounded-full` is reserved for genuine circles (dots, spinners, radios, avatars, circular icon-only buttons); no pill/capsule shapes anywhere (ui8 phase 4) — every chip, badge, counter, status indicator, and thin bar track sits on the box-radius family (`rounded-md` for small chips, `rounded-sm` for tiny counters and bar tracks, `rounded-lg` for larger surfaces).

### Colors (semantic, light/dark via `.dark`, theme via `data-theme`)

`--background` / `--foreground`, `--card`, `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring` — each with a `-foreground` pair where applicable. Nav-specific glass tokens (`--nav-glass-*`, `--nav-tab-*`, `--nav-input-*`) also live in `src/index.css`.

Semantic status tokens (ui12 phase 4): `--status-done` (green, own light/dark pair), `--status-working` (aliases `var(--primary)`), `--status-idle` (aliases `var(--muted-foreground)`) — Tailwind `text-status-done` / `text-status-working` / `text-status-idle`. The working/idle aliases resolve per-theme and under the custom accent, so named themes never override them; new themes only need to leave them alone. All task-level status icons and done/total counters (task rows, the row and top-bar counters when complete) go through these tokens — never hardcode emerald/accent classes for status. Job-level icons opt out via `TodoStatusIcon tone="mono"` (ui13 job 1): completed/working render in the foreground ink; counters stay on the tokens.

Named themes (ui8 phase 4, expanded ui15 job 6): a theme is a full color-token set with light and dark variants, selected in Settings → Appearance, persisted in localStorage `color-theme`, applied as `data-theme` on `<html>` by `ThemeContext`. The catalog lives in `src/shared/themes.ts`; the base `:root`/`.dark` pair in `src/index.css` IS the default **Steel Blue** theme, and each additional theme (**Graphite**, **Ink**, **Moss**, **Copper**, **Dune**, **Glacier**, **Plum**, **Marine**, **Lichen**, **Berry**, **Sienna**) is a `[data-theme='<id>']:not(.dark)` / `[data-theme='<id>'].dark` override block covering every color token plus `--beam-ink` and the nav tokens. Only color tokens vary per theme — radius, type, and spacing are shared. The browser `theme-color` meta follows the active theme's computed `--background`. New themes get a full token pair in both files; never a partial override.

Layered themes (ui10 phase 3): a theme is three independently designed layers — the surface ramp (`--background`/`--card`/`--secondary`/`--border`), the ink pair (`--foreground`/`--muted-foreground`), and the accent family (`--primary`/`--ring`/nav glow-focus) — so surface tint, ink temperature, and accent hue are deliberate separate choices (Ink is navy on warm paper with cool ink; Moss is green on cool stone with espresso ink; Copper is terracotta on cool porcelain with sepia ink; Dune is oasis teal on sand with brown ink; Glacier is alpine blue on ice with warm ink; Plum is antique gold on lilac chalk with aubergine ink; Marine is coral on sea glass with navy ink; Lichen is olive on pale mineral with slate ink; Berry is berry on blue slate with walnut ink; Sienna is fired clay on sage gray with violet-black ink). Never sweep one hue across every token. Each theme carries a palette preview in `src/shared/themes.ts` (`dots`: surface, secondary, ink, accent per mode) rendered by `ThemePaletteDots` in the theme selector options — keep `dots` in lockstep with the CSS tokens when a theme changes. Preview dots are 10px, sit at the option's right edge, and fade in only while that option is hovered or keyboard-focused so the label owns the resting row.

Custom accent (ui10 phase 3): the Appearance tab's Accent row is a color swatch (`hsl(var(--primary))` background) wrapping a native color input, with a Reset text button when active. The picked `#rrggbb` persists in localStorage `custom-accent`; `ThemeContext` applies it as inline overrides of the accent token family on `<html>` — `--primary`, `--primary-foreground` (auto light/dark type by lightness), `--ring`, `--nav-tab-glow`, `--nav-tab-ring`, `--nav-input-focus-ring` — for both modes (dark lifts lightness to ≥62 so the accent reads on dark surfaces). It rides on top of whichever theme is active and recolors everything routed through `primary`/`ring`, including the mark; the selector dots swap their accent dot for the custom swatch. `--beam-ink` stays neutral and is never overridden.

- Accent: silver-leaning silver-blue. Light `--primary: 211 20% 45%` (`--primary-foreground` white); dark `--primary: 211 22% 64%` (`--primary-foreground` near-black, the lighter accent needs dark type). `--ring` and the nav glow/focus tokens carry the same hue per theme. Every accent use (send button, links, active states, selection ticks, progress ring fill, focus rings) goes through `primary`/`ring` utilities — never hardcode blue or orange Tailwind palette classes. Warning states use the amber family; nothing uses the orange family.
- User message bubble: `bg-secondary text-secondary-foreground` (lighter gray bubble on the darker background in dark mode, white text). No blue bubble, no avatar circle.
- Secondary/metadata text: `text-muted-foreground`.
- Icons are monochromatic app-wide in every theme (ui8 phase 4): control, menu, header, and empty-state glyphs render in `currentColor` / `text-muted-foreground` / `text-foreground` — never a decorative, identity, or destructive-intent color (no red trash cans, no per-language file-icon colors, no colored provider logos; `ClaudeLogo` is `fill-foreground`/`fill-background`). Destructive intent conveys through copy and confirm dialogs. Data inks stay data: diff add/remove, chart/legend colors, success/failure state glyphs, live status dots, task priority encoding, attention amber, recording red, terminal green. Semantic status is the standing exception (revised 2026-08-25, narrowed ui13 job 1): TASK-level status icons and every done/total counter carry meaning in color through the `--status-*` tokens — done green, working accent, idle muted ink. JOB-level icons are back to monochromatic (`TodoStatusIcon tone="mono"`): a completed job's check and a working job's ring/spinner render in the foreground ink, its filled ring segments likewise — jobs mono, tasks semantic. Colors carry meaning only; everything else stays monochromatic.

### Shadow & spacing

- Bubbles and inline chat elements: flat, no shadow beyond what the component already carries.
- Popovers/menus: `border border-border bg-popover shadow-lg` with `rounded-md`/`rounded-lg`.
- Usage-alert toast (ui15 job 7): `AppContent` stacks one `data-slot="usage-alert-toast"` per threshold crossing at the lower-right inset (viewport-safe `min(22rem, 100vw - 2rem)` width). It extends the existing toast shell: `rounded-lg border-border bg-popover shadow-lg`, amber `BellRing`, 14px medium title and 12px muted body, using `popout-enter popout-enter-up` with the global reduced-motion collapse. Threshold state dedupes at the server; the client keeps every simultaneous crossing visible for six seconds rather than overwriting the stack.
- Mobile safe-area and nav spacing variables (`--mobile-nav-*`, `--safe-area-inset-*`) are defined in `src/index.css`; use them, don't hardcode offsets.
Shared primitives (shadcn-style, use these first): `src/shared/view/ui/`
- `Button.tsx`, `Input.tsx`, `Badge.tsx`, `Card.tsx`, `Alert.tsx`, `Dialog.tsx`, `Tooltip.tsx`, `Collapsible.tsx`, `ScrollArea.tsx`, `Command.tsx`, `ActionMenu.tsx`, `PillBar.tsx`, `PromptInput.tsx`, `Reasoning.tsx` (thinking accordion), `Shimmer.tsx`, `Skeleton.tsx`, `Confirmation.tsx` — exported through `src/shared/view/ui/index.ts`. (`Queue.tsx` was retired; task lists render through the beUI `TodoList`.) `ActionMenu` items take an optional `trailing` node — right-aligned `text-[10px] tabular-nums text-muted-foreground` metadata on the label line. `Tooltip` is collision-aware (ui14 job 2): the portal box is measured before placement and its centered position clamps inside the viewport with a 6px margin, while the arrow shifts back by the same amount so it stays anchored to the control's center — near any screen edge the box slides inward and no text clips; every tooltip site inherits this.
- `Skeleton.tsx` (`data-slot="skeleton"`, ui11 phase 11) is the one app-wide loading placeholder: a content-shaped `animate-pulse rounded-md bg-muted/70` block (static under reduced motion) composed per surface into the shape of the element still arriving — transcript rows (`data-slot="transcript-skeleton"` in ChatMessagesPane), sidebar project rows and archive cards, the worker header's run label, settings sections that fetch. Skeletons hold the real element's dimensions and give way to content, never to a blank; never a centered spinner block for content that is loading.
- `Badge.tsx` carries the beUI animated-badge skin — `rounded-md` rectangle (no pill, ui8 phase 4), `font-medium tabular-nums`, tinted `border-{color}/30 bg-{color}/10` colorways through semantic tokens (primary for default/info/loading, destructive for danger, emerald for success, amber for warning). Passing `status` opts into the animated state treatment: rolling icon/text swaps on status change, spinning loader with pulse for in-progress states; suppressed under prefers-reduced-motion. Wired on the worker/planner header state chips — never invent status badges elsewhere. Tool rows carry NO status chips (ui12 job 10): tool status is the leading icon (see the tool-row entry).
- `src/shared/view/beui/` — the vendored beUI kit (beui.dev), rethemed to this app's tokens: `MessageScroller` (follow-output transcript scroller — ResizeObserver keeps the live edge pinned, smooth-scrolling as streamed content grows; its programmatic-scroll guard clears on arrival at the end or on reader input, never on a fixed timer — ui13 job 15: a large landing animates longer than any short timer and the tail of the engine's own scroll used to read as the reader leaving, so follow switched off while the turn kept streaming), `StreamingResponse`/`useStreamedReveal` (live-turn reveal: word-boundary stepping at ~126 chars/s base plus a backlog-proportional catch-up rate so playback never lags real arrival — ui9 B2), `BrailleLoader` (horizontal ASCII Braille loader), `AgentDisclosure` (transform-only collapsible reveal), `SwapText` (roll label swap), `textShimmer` (the one text-shimmer treatment for in-progress labels), `ease.ts` (the motion springs/easings — use these, never ad-hoc curves). ui9 B2 additions vendored from beautifului.dev (www.beautifului.dev, MIT): `PixelLoader` (3×3 pixel-grid loading mark, variants drive/dots/orbit, keyframes `bui-pixel-on` in `src/index.css`, cells freeze dim under reduced motion) and `Thinking` (`data-slot="thinking-trace"`, the expandable agent trace — star-glyph header with shimmer active label / settled label / spring-free 300ms chevron, grid-rows collapse, left rule, fade-up rows — four modes: `steps` spinner→check step rows, `reasoning` prose, `search` query line + favicon source rows via `useFavicon`, `coding` mono rows with +/− counts). Phase-4 additions: `ActionSwapIcon` (blur icon swap for state-changing controls), `BeuiSwitch`, `BeuiTabs` (pill/underline/segment tabs with the `TABS_INDICATOR_SPRING` layoutId indicator), `BeuiSelect` (bouncy unfold select), `BeuiRadio` (`RadioGroup`/`RadioDot` gliding indicator), `NumberTicker` (rolling digit columns for live counts), `Loader` (dot-matrix + dither loading marks), `TodoList`, `Citations` + `useFavicon`, `ToolApproval`. Phase-5 additions: `BorderBeam`/`BorderBeamOverlay` + `useBeamPresence` (the activity shimmer — see App chrome), `MarqueeLabel` (overflow-aware row label from the ai-sidebar), `BounceIndicator` (bounce-sidebar active dot on a curved spring path). New collapsibles, controls, and loaders on the chat surface extend this kit.
- Control laws from the phase-4 adoption: any control whose icon changes with state renders it through `ActionSwapIcon`, never a hard cut (composer submit send/stop/queue, voice mic). Values that change while the user watches (composer character counter, activity-indicator elapsed time, context-popover header value) render through `NumberTicker` with a `format` callback — digits roll in place, unit glyphs (`k`, `M`, `%`, `m`, `s`) render as plain text, so the displayed string is byte-identical to the static version; inside the ticker every non-digit glyph (and prefix/suffix) gets the same fixed 1.1em box and matching line-height as the digit columns (ui9 B6), so digits and unit glyphs share one baseline instead of drifting with the inherited line-height. Content-shaped surfaces awaiting data (chat transcript, sidebar project and archive lists, worker header run label, fetching settings sections) render the shared `Skeleton` in place (ui11 phase 11); the beUI `Loader` remains for action and connection states (search in progress, session boot/generation, code/PRD editor overlays, shell connection overlay, git panel views — `dot-matrix` app-wide, `dither` on shell/terminal surfaces); inline button spinners keep `Loader2`/spin. The composer model-switcher pill rolls its model/effort labels through `SwapText` on selection.
- `BeuiSwitch` is the one toggle: h-7 w-12 track `rounded-md`, h-5 w-5 thumb `rounded-sm` (box radius, not a pill), checked `bg-primary`, spring-driven thumb with press squish-stretch; optional `thumbContent` centers an icon in the thumb (DarkModeToggle's Moon/Sun). `SettingsToggle` and `DarkModeToggle` delegate to it.
- Tabs: `BeuiTabs` — a spring `layoutId` indicator glides between triggers. Underline variant (h-px `bg-primary`) drives GitViewTabs; segment variant (`bg-primary` pill on the rounded-md step) drives MainContentTabSwitcher inside the old muted bar chrome. Icon-only tab strips (sidebar Projects/Chats/Archive, the Settings tabs) are `IconTabs` (see the sidebar entry), which rides the same spring.
- Selects: `BeuiSelect` replaces native `<select>`s — the panel bouncily unfolds out of the trigger and flips upward when out of room. Trigger `rounded-lg border-input bg-card` with `ring` focus; panel on the popover spec; selected tick `text-primary`. Homes: Appearance tab selects, LanguageSelector.
- Radio: `BeuiRadio`'s `RadioDot` — ring-and-dot whose inner `bg-primary` dot glides between options via shared `layoutId`. AskUserQuestionPanel's single-select rows compose it with `SPRING_PRESS` tap feedback; multi-select rows keep the checkmark.
- Context menus: the file-tree right-click menu unfolds with the beUI clip-path morph — the panel expands from an 8px-radius window at the cursor point (0.3s EASE_OUT), items use the spring shared-layout highlight instead of hover backgrounds, and danger items keep the rose colorway on the LABEL only — the icon renders neutral (icons are monochromatic app-wide, ui8 phase 4). Panel: `min-w-56 p-1.5 rounded-lg border-border bg-popover`; `data-slot="context-menu"`. Keyboard opens and reduced motion skip the morph.
Global CSS (scrollbars, transitions, chat containment classes, placeholder colors): `src/index.css`. Scrollbars are one app-wide treatment (ui8 phase 3): thin and trackless — 4px webkit width, transparent track, `muted-foreground/0.35` thumb on 2px radius, `scrollbar-width: thin` everywhere; never style a per-surface scrollbar.
