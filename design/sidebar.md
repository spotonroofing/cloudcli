# Sidebar

App chrome
- Sidebar identity & activity (phase 5, on the beUI ai-sidebar anatomy; selection redone in ui8 phase 3): desktop project and session rows are borderless `min-h-9 rounded-lg px-2` rows with NO filled hover or selected background — hover and selection are quiet ink shifts (`text-muted-foreground hover:text-foreground`, selected `text-foreground`), focus keeps the inset ring. The bounce dot is the one honest indicator of the open chat: a 6px `bg-primary` dot (`BounceIndicator`) arcs on a curved spring path to the open session's row (`data-bounce-key` on chat rows; the indicator measures the visible stamped element and seats 4px inside the destination row's own left edge — x is measured per row, ui11 phase 15, so an indented Projects-tab row keeps the dot tight against its title block instead of out at the pane edge — and re-seats through resize + DOM-mutation observers; its observers attach in a passive effect because a child's layout effects run before the host container's ref exists). When the dot's destination row isn't rendered — the open chat's project is collapsed, or a project is open as a workspace row — the project row carries the static `data-slot="project-open-indicator"` dot (`bg-primary/70`, same seat). Project rows show the project icon tile, an overflow-aware `MarqueeLabel` (hover scrolls an overflowing name, fitting names never move; `flex-initial` so it hugs its text), the chat-count numeral inline at the title's end (`data-slot="project-session-count"`, never hover-revealed), hover actions, and a spring-rotated chevron. ui14 job 12 row laws: the hover actions are display-hidden at rest (`hidden group-hover/project:flex`, `touch:flex` on coarse pointers) so only the count and chevron hold fixed slots and the name takes the row's free width; a project row or chevron click is a pure dropdown toggle — it never selects the project or touches the workspace, a project opens only when one of its chats is clicked; project order is starred first, then last-opened-by-Willem (`project-last-opened-v1`, written on his open actions only), then name — session activity never reorders the list; the orange "needs attention" dot is gone entirely (the bounce dot and the activity beam are the only row indicators); a row's age reads from `sessions.updated_at`, which the Claude synchronizer derives from the transcript's last real user/assistant message — never file mtime, identity wiring, or a project move — so watcher cycles, label-pass marker lines, and watchdog touches cannot move a chat's age; and the hover marquee runs only while the pointer is on the row — on leave it stops and slides back to rest on `MarqueeLabel`'s 0.4s eased return, never a blink or a continued scroll. Session rows carry NO provider icon tile — just label, count badge, age, and the options menu. A chat row is the ONE shared `ChatRow` component at every viewport in both the Projects tab and the Chats tab (ui11 phase 15): identical padding, typography, chevron/dots trailing control, and shared `ChatRowMenu`; the only sanctioned differences are the Projects-tab nesting indent and the Chats-tab project-name subtitle lead. Session names are `text-[13px] leading-4` in BOTH tabs — never `text-sm`. The session block unfolds/folds with a 0.18s EASE_OUT height+opacity reveal, indented by depth padding (`pl-5`), no tree rule, with `space-y-1` breathing room and a margin under the New Session button. Project editing is the `ProjectEditDialog` (shared Dialog chrome, labeled Title / Path / Planner memory name fields; the path is editable — the rename API re-points the project row and its sessions).
- Project icons: `iconDataUrl` on the project payload (repo-root `app-icon.svg` → `icon.svg` → `icon.png` convention, else the bundled SpotOn icon from `public/project-icons/`, else null). `ProjectIcon` renders it at `h-4 w-4 rounded-[3px]` in the ai-sidebar `size-5` grid tile; the default is lucide Folder/FolderOpen — the beUI default, never a custom glyph.
- Activity shimmer: the vendored `BorderBeam`/`BorderBeamOverlay` (`src/shared/view/beui/BorderBeam.tsx`, npm `border-beam` engine) — rotate mode, mono colorway, ink `--beam-ink` (light `211 10% 42%`, dark `211 16% 78%`; a neutral silver, never the accent), ambient strength 0.4. A mid-turn chat row carries the beam (it replaced the old green pulse dot); a project row carries it while any of its sessions runs AND the project is collapsed — expanding hands the shimmer to the chat rows. "Runs" means planner and worker alike (dispatched, direct, maintenance): the count comes from the same enriched running-runs poll the counter drawers use, and the beam clears when all are idle. Worker-origin sessions (dispatched builds, verify stages, direct runs) never list as chat rows, so an expanded project row keeps the beam for them (`unlistedRunningCount`, codex job 5) instead of handing off to a row that does not exist; the poll itself reads a chain runner's live build and verify sessions off the chain registry (`listActiveDispatchRuns`), since the runner never passes through the in-server run registry. Mount beams through `useBeamPresence` so every appearance/disappearance is the engine's fade, never a hard cut.
- Active-session counters (ui8 phase 3): one full-width two-column bar (`data-slot="activity-counter-bar"`) pinned to the sidebar bottom above Settings — planner left (Compass + primary), worker right (Hammer + emerald), rectangular on the app radius (`rounded-lg border`, no pill). Counts roll through `NumberTicker`; a column breathes (`animate-counter-breathe`, opacity/filter swell, reduced-motion off) while its count is nonzero; the whole bar hides when both are zero. Each column is a button while its count is nonzero (ui10 phase 4): clicking jumps to the first running session of that kind (quiet `hover:bg-accent/60`, ring focus). The collapsed rail shows the same pair as `RailCounter` (icon left, number right, same breathing, same hide-at-zero) above the rail's Settings button. Planner = origin `planner` or null, worker = `direct`/`dispatch`/`external` — the same split as the pane headers.
- Footer taskbar and integrated drawers (ui13 job 4): the sidebar footer's stacked rows became one left-aligned row of icon-only controls (`data-slot="sidebar-taskbar"`, `px-2 py-1.5 gap-1`) — Settings, account (`AtSign`, `data-slot="account-switcher-trigger"`, `title` carries the active email), Memory (`BookMarked`, `data-slot="memory-viewer-trigger"`) — each a `touch-hit h-9 w-9` ghost icon button (44px hit area), no labels. The open drawer's icon reads selected (`bg-accent/60 text-foreground`); while any drawer is open the other icons dim to `text-muted-foreground/40`. The footer drawer shell (`SidebarFooterDrawer.tsx`) has no panel chrome on desktop: no portal, no `bg-popover`, no border/shadow — an in-flow region on the sidebar's own background that unfolds between the footer's divider and the taskbar by animating height 0↔auto (0.3s EASE_IN_OUT ramp both ways — a height collapse cannot leave an exit sliver), growing the footer so the lists above squish up while the taskbar stays put; a trailing `nav-divider` inside the animated region separates content from the taskbar. Escape closes in the shell; a press outside the footer closes via `SidebarFooter`'s document pointerdown listener; a second trigger tap toggles. Drawers and surfaces are mutually exclusive both ways (ui14 job 4): opening a drawer closes any surface (`onDrawerOpened`) and a surface opening (Settings, Memory) ramps the open drawer closed through the same height collapse. No divider bar sits on top of an open desktop drawer: the footer's divider above the drawer region fades out (0.3s opacity) while a drawer is open and the drawer's own top padding separates it from the list. Phone: a full-width `bg-background border-t rounded-t-lg` bottom sheet portaled over the `bg-background/60 backdrop-blur-sm` scrim, same ramped curve (0.32s EASE_IN_OUT, full `y: 100%` exit).
- Account switcher (ui8 phase 6; drawer in ui11 phase 5; integrated ui13 job 4; revamped ui14 job 4): the taskbar's AtSign icon opens `AccountsPanel` (`src/components/sidebar/view/subcomponents/AccountsPanel.tsx`, `data-slot="accounts-panel"`) on the footer drawer shell — never a centered popup. No heading and no subtitle (a cswap switch rewrites the shared credential store that running Claude sessions re-read on token refresh, so no one-line claim about running sessions is true — the panel says nothing). The list sits in `px-2 pt-3 pb-2` (top padding, no divider bar). One borderless `rounded-lg px-2 py-2.5` row per cswap account (`data-slot="account-row"`, the sidebar row anatomy): a `w-4` mono slot numeral, the name (`data-slot="account-name"`, `text-[13px] font-medium`, alias or email) in full, and the stacked usage meters under it indented `pl-6` to the name's left edge. The active row is the `bg-accent/40` wash with the name in `text-foreground`; other rows are transparent with the name muted — there is no dot. Row actions (use, hold/return, move up/down; `h-7 w-7` ghost buttons, `data-slot="account-actions"`) are `display: none` at rest on desktop so the name owns the row, and appear on `group-hover` / `group-focus-within` — the only time the name truncates with an ellipsis; touch shows them always with `touch-hit`. Meters (`data-slot="account-usage-bar"`): `w-9` uppercase micro label, the `h-1 rounded-sm bg-muted` track (fill `bg-primary` / `bg-amber-500` ≥70 / `bg-destructive` ≥90 as data encoding) taking the rest of the width, `w-7` percent, `w-10` cswap reset countdown (clock fallback); 5h, 7d, then per-model windows. Add account is the real flow, no token or API-key field anywhere: the `Add account` row (`data-slot="account-add-trigger"`) expands to a two-step block (`data-slot="account-add-steps"`, `bg-muted/30`) — `1 Log in` with a mono `claude /login` chip (`data-slot="account-add-login"`) and `2 Add to cswap` with a `cswap add` chip (`data-slot="account-add-add"`), each opening the shell window with that command (`env -u CLAUDE_CONFIG_DIR BROWSER=/usr/bin/true claude auth login` / `env -u CLAUDE_CONFIG_DIR cswap add`, run against the machine-global profile like every server-side cswap call; the no-op BROWSER keeps the server machine from opening its own browser, so the terminal's printed sign-in URL is the way in), plus a "Waiting for it" micro status and Cancel. While the block is open the panel re-reads `/api/accounts` every 5s and when a shell window closes, and folds the block away once a slot appears that was not in the list when the block opened or the active slot changed (`src/components/sidebar/utils/accountsAdd.ts`). Server: `server/modules/accounts` shells the machine's cswap with `--json` and `CLAUDE_CONFIG_DIR` stripped (list, status, switch, disable, enable, swap — no add route); a switch re-mirrors the default Keychain credential into a scoped instance's own service (the cloudcli-dev-start.sh mirror, now also post-switch). ChatGPT group (codex job 3): below the Add account row, an uppercase micro group header `ChatGPT` (`data-slot="account-group-chatgpt"`) then one `account-row` (`data-account="chatgpt"`, `data-state` ok / logged_out / stale) on the same row anatomy with the OpenAI mark in the numeral slot, the login email as the name, the plan name as the bordered micro tag (`data-slot="account-plan"`), and the 5h / 7d `account-usage-bar` meters under it (same countdown/clock format as the Claude meters, a dash when Codex reports no window of that size); under the meters the muted meta line (`data-slot="account-usage-meta"`): "updated Xs ago" ticking every 10s, or "no usage recorded yet" when no rollout carries a reading. No use / hold / move controls (one login, nothing switches it). Logged out or a token stale for 30 days: no meters, one line "Logged out." / "Login stale." plus the mono `codex login` fix (`data-slot="account-login-fix"`). Data: `/api/accounts` carries `chatgpt` (`{email, plan, state, usage: {fiveHour?, sevenDay?, readAt} | null}`) from `server/modules/providers/services/chatgpt-account.service.ts`: the email and plan decoded from the id token in `~/.codex/auth.json` (never the token), the meters from the newest `token_count` event's `rate_limits` across `~/.codex/sessions` (a rescan on every read, newest file first, stopping at files older than the reading in hand). Live: the Codex session synchronizer hands every changed rollout to the service, which pushes a `chatgpt_usage` frame when the reading is newer; the panel subscribes only while open, and nothing polls.

- Memory surface (ui12 phase 7; full-sidebar ui13 job 5; curated-first ui13 job 8; one view + prompt edits ui14 job 3; prompt fit ui15 job 4): the footer taskbar's BookMarked icon (`data-slot="memory-viewer-trigger"`) toggles `MemorySurface` (`data-slot="memory-surface"`) on the full-sidebar surface shell. One view only: the curated memory document — `planner/_global/GLOBALMEMORY.md` in the spoton-worker repo, the planner-maintained record of Willem himself — rendered as clean prose Markdown (`data-slot="memory-curated"`, no row chrome, no section labels) under a `text-sm font-medium` "Memory" header with the BookMarked icon. No tabs: the Internals view and the Project/Global toggle are gone with nothing replacing them (the technical layers are not a user surface). Editing is the prompt box at the bottom (`data-slot="memory-prompt"`, Claude.ai style): equal `py-3` breathing room above and below the shared `PromptInput` enclosure, with an autogrowing `PromptInputTextarea` (placeholder "Iterate memory...", `13px/20px` on desktop, `text-base` on phones) and an `h-7 w-7` `PromptInputSubmit` — the composer's control scale, never larger. Enter applies, Shift+Enter breaks a line. Apply runs `POST /api/memory/curated/edit {instruction}`: a one-off headless `claude -p` session on the server (`--no-session-persistence`, tools limited to Read/Edit/Write, cwd the memory repo — not a chat, not a planner session) applies the instruction to the document by the document's own header rules (add, update in place, rotate stale), then the server commits (`memory: <instruction>`) and pushes the memory repo and answers with the new content; the send button shows the spinner while it runs (textarea disabled) and a `Check` for 1.6s after, then the arrow again, and the document re-renders from the response with no reload. Repeatable. Errors and post-edit warnings ("Committed, but the push failed.") sit inline under the box in `text-xs text-destructive` (`data-slot="memory-prompt-note"`); "No change" in the muted cut when the session left the file alone. The surface's own edits never produce a transcript row (the memory service holds a sentinel claim on the file while the edit runs). Data: `GET /api/memory/curated` → `{content}`. Import hook: at memory-watcher init the server looks for `planner/_global/claude-ai-memory-export.md`; if present it renames it `.imported` first (live and dev share the repo) and runs the same one-off edit with an import instruction (keep only what applies to how Willem works and his coding projects, drop unrelated personal facts, merge under the right sections, dedupe), committing both; absent, nothing happens. Desktop keeps the full-sidebar surface and its established spacing. Phone uses the shared bottom-sheet language inside the visual-viewport-pinned sidebar: a scrim, rounded top edge, internally scrolling document body, and prompt bar pinned above the taskbar and software keyboard.
Hover title scan + tooltip law (ui13 job 3): every truncating chat-row and job-row title reveals itself with the beUI `MarqueeLabel` hover scan — `ChatRow` titles (both sidebar tabs) and the jobs view's job/task unit titles scroll their overflow while the row is mouse-hovered and rest clipped otherwise, exactly like project rows; the scan is fine-pointer only (mouse enter/leave — touch taps act before hover matters; on touch the full name is readable in the pane header once the chat opens). Tooltips (native `title` or the shared `Tooltip`) exist ONLY on icon-only controls whose purpose is not self-evident — toolbar icon buttons, status glyphs/badges, drag handles, the collapsed-rail counters and job rings, meters. Never put a tooltip on an element whose visible text already says what it is (rows, titles, truncated paths/values — text echo), and not on self-evident icon controls (close/dismiss X, search-clear X, send arrows, prev/next steppers beside an n/N readout, expand/collapse chevrons); those keep aria-labels only.
