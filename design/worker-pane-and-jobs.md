# Worker pane and jobs

Job token totals (ui15 job 11, row placement corrected in ui16 job 2, spend/cache split in ui17 job 19): every Claude or Codex build session in the jobs history carries its whole-session token cost from the provider-native source, split so the cache never inflates it. The primary figure is spend, fresh input plus output: Claude sums unique `message.id` usage records in its JSONL counting `input_tokens` and `cache_creation_input_tokens` only; Codex takes its rollout's newest cumulative `total_token_usage` less `cached_input_tokens`. Cache reads (the whole context re-read every turn) are summed on their own and render beside the spend as a quieter compact figure (`jobs-sidebar-cache-reads`, `data-cache-read-count`, `24.9M cached`), never added into it — summing them showed 12 to 14 million "spent" against 133 thousand of real output fifteen minutes into a unit. The exact mono total renders only at the drawer bottom beside total time (`jobs-sidebar-token-total`); collapsed rows carry no token figure, and `data-token-count` preserves the source integer for checks. No estimate or context-window snapshot substitutes for a missing source.

- Live loading truth (ui15 job 13): a worker pane whose jobs preference restores open immediately renders `jobs-sidebar-skeleton` row shapes until the first `worker-runs` snapshot lands; the delayed response replaces them in place. The worker run-title slot uses the same shared primitive. Neither surface flashes an empty list or a premature no-data state.

- Pause state (pauseresume job 1; promote boundary hold ui18 job 0): a paused chain remains in the same jobs history. Its current row carries `data-status="paused"`, replaces the working spinner with the monochrome pause-in-circle mark, and leaves later jobs idle; resume updates that same chain and row rather than adding a run. A promote-requested hold is set durably on the chain record without signaling its runner; after the current job commits and its verifier settles, the runner exits cleanly at the unit boundary and the paused row adds `holding for promote` (`jobs-sidebar-hold-label`) until the unchanged resume path starts the next uncommitted job. A promote never uses the mid-unit WIP parking path.

- Windowing layer (ui13 job 10): the desktop surface of every project is a pane strip (`PaneStrip` in `src/components/app/workspace/`, `data-slot="pane-strip"`) — its windows (Planner, Worker, Files, Source Control; extensible through `useProjectWindows`'s `WindowId`) tiled side by side inside the workspace grid, no freeform floating, no z-order. Each window is `open` (a tiled pane, `data-strip-pane`), `rail` (the thin `w-6` rotated-text rail, `data-slot="pane-rail"`, attached in place so it squishes the nearest open pane), or `closed` (absent; files/git only — planner and worker never fully close). State + per-pane flex weights persist per project in the cloud-synced `project-windows-v1` record (`useProjectWindows`), so each open project keeps its own window set across switches, reloads, and devices. The window selector (`WindowSelector`, an `ActionMenu` behind a `PanelsTopLeft` ghost icon in the planner pane header) lists the windows with a check on the open ones — selecting an open window closes it (planner/worker to their rails, files/git away), a closed one opens; opening an auxiliary window resets the strip to the even split so planner and worker squish evenly and stay equal. Opening or closing the jobs column is the same geometry boundary: that project's weights normalize once; while the side column is present, Worker carries the responsive `JOBS_COLUMN_BASIS` (`min(16.25rem, calc(33.333cqw + 1.25rem))`: 20px wider than ui14 below a 260px cap) and the jobs view uses that exact width, so Planner and the remaining Worker transcript receive equal flex space. Closing removes the basis and restores the even Planner/Worker split. Auxiliary windows render on `WindowPane` (the standard slim header: muted icon + label + trailing X that collapses to the rail). Files defaults closed and hosts `FileTree`; Source Control defaults closed and hosts `GitPanel`. Neither is a tab anymore — desktop stays chat-only in tab terms, and on mobile the same selector (in the planner pane header) routes Planner/Worker/Files/Source Control to full-pane views over the existing tab state. Pane-divider law (ui13 job 10): every pane divider — the strip's window dividers and the workspace's row/column dividers — is `PaneDivider`: it rests hairline-thin (1px `bg-border/50`, the sidebar edge's weight) and on hover or drag ramps (0.2s EASE_IN_OUT) to the `w-1` grab width in `bg-primary` with the resize cursor; the pointer hit area (`data-slot="pane-divider-hit"`) is ~13px, wider than the visual line, for touch. Snap reachability derives from the two panes' actual, asymmetric CSS minimums; an undersized pair normalizes to its one proportional boundary instead of storing or advertising an impossible stop. The URL-driven selection is always the primary row; extra rows manage their own planner sessions (WorkerPane pattern) and never touch the app URL or the global selected session.
- Divider snap (ui15 job 1): every `PaneDivider` drag — the strip's window dividers and the workspace's row/column dividers — tracks the pointer instantly and lands on notches (`useSnapDivider` + `SnapGuides` in `src/components/app/workspace/dividerSnap.tsx`).
