# Mobile

One design across form factors: the desktop-only gating from UI rounds 1–3 is removed, so mobile renders the same language (radius token, silver-blue accent, unified composer with Handoff, grouped model switcher, usage ring + left-anchored popover, tool-row treatment, sidebar segmented control and bottom-pinned Settings, self-hosted font). Mobile-only functional controls with no desktop equivalent (tab rail, drawers, bottom sheets, keyboard insets, create-project) stay, restyled with these same tokens — never a parallel style. The mobile sidebar otherwise mirrors the desktop structure exactly (ui13 job 9): the same three icon tabs, the same footer taskbar at the natural bottom (safe-area padded), the same drawers — rendered as bottom sheets per the sheet law; no mobile-only sidebar views (the Running tab is gone — active sessions live in the planner/worker counter drawers on both form factors, and the quick-settings edge flyout is gone — its settings live in the Settings surface).
Mobile parity laws (ui7 phase 8): the mobile sidebar project/session rows are the same beUI ai-sidebar row anatomy as desktop (borderless `min-h-11 rounded-lg` rows — 44px-tall touch variant of the desktop `min-h-9` — icon tile, MarqueeLabel, count numeral, spring chevron), with actions always visible instead of hover-revealed; session actions open the bottom sheet (rename / move / copy / delete on token colorways). The mobile top bar is hamburger + tab rail only, on the pane-header bar chrome — the old chat-title block is gone on both form factors; titles live in the pane header. The sidebar refresh button is desktop-only; mobile refreshes by pulling the sidebar list down (`usePullToRefresh` + the indicator row in SidebarContent, `data-slot="pull-to-refresh"`). Touch laws on every mobile-reachable control: 44px minimum hit area — visually small controls keep their size and extend the tap area with the `touch-hit` utility (`src/index.css`, pointer-coarse only, requires `relative`); no action gated behind hover (fence hover reveals with `md:` or `touch:opacity-100`, never `sm:`); text inputs 16px below md (`text-base md:text-sm`) so iOS Safari never zooms on focus; bottom chrome pads `env(safe-area-inset-bottom)`; full-height mobile surfaces use `dvh`, never `vh`/`h-screen`.
- Mobile safe-area and nav spacing variables (`--mobile-nav-*`, `--safe-area-inset-*`) are defined in `src/index.css`; use them, don't hardcode offsets.
- Phone chrome (ui14 job 11): one switcher. The old top strip (hamburger + Chat/Worker tab rail, which scrolled sideways) is gone; on a phone every full-pane view — Planner, Worker, Files, Source Control — is topped by the same slim pane header (`data-slot="pane-header"`, `overflow-hidden`, nothing in it scrolls) carrying the menu button (`MobileMenuButton`) at the left, the window selector at the right, and the chat/shell toggle (`data-slot="pane-view-toggle"`) on the two chat panes; the selector is the only way between windows. The top-most bar carries `.mobile-top-bar` (`src/index.css`: safe-area-inset-top plus `--header-base-padding`, in Safari and home-screen mode alike — the app shell's inline `top` bypasses the old PWA offset on `.fixed.inset-0`) — the sidebar header uses the same class on phones. The phone sidebar (`data-slot="mobile-sidebar"`) fills the app shell edge to edge (no partial drawer, no scrim), slides on the 320ms `cubic-bezier(0.77,0,0.175,1)` ramp both ways, and closes from the X in its header (`data-slot="mobile-sidebar-close"`) or by opening a chat. Keyboard: `index.html` keeps `interactive-widget=resizes-content` (Chrome for Android shrinks the layout viewport; WebKit ignores the key), and for iOS the app shell (`data-slot="app-shell"`) is pinned to the visual viewport by `AppContent`'s visualViewport hook (`--vv-top` / `--keyboard-height` from `offsetTop`, `height`, resize + scroll while the keyboard is up, a re-read on `focusout`), so the composer rides the keyboard's top edge; the composer's bottom padding is `--composer-bottom-pad` (home-indicator inset at rest, 8px under `html[data-keyboard="open"]`); programmatic refocus uses `focus({ preventScroll: true })`. Pane shell (`PaneShell`, `src/components/app/workspace/`): the shell toggle opens a terminal in the project's cwd resuming that pane's session (`claude --resume <provider id>`), the server pre-trusting the folder in this instance's config dir (`trustProjectForClaude`) so no trust prompt appears; while the session is mid-turn the toggle shows the transcript read-only instead (`data-shell-mirror`, prompt bar hidden, permission requests still shown, a `data-slot="pane-shell-busy"` status row) and the real shell takes over once the turn ends. While the shell view is open the pane's queued-draft idle flush is held (`holdQueuedFlush` through `ChatInterface`), so a turn ending never auto-sends into the session the terminal is about to resume; the draft flushes when the shell closes. Known constraint: the guard is one-way — once a terminal has resumed the session, a prompt typed into that terminal and a send from the same session on another device would both write the session file; the terminal stays cached server-side for 30 minutes after the view closes.
