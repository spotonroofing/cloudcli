# Mobile

One design across form factors: the desktop-only gating from UI rounds 1–3 is removed, so mobile renders the same language (radius token, silver-blue accent, unified composer with Handoff, grouped model switcher, usage ring + left-anchored popover, tool-row treatment, sidebar segmented control and bottom-pinned Settings, self-hosted font). Mobile-only functional controls with no desktop equivalent (tab rail, drawers, bottom sheets, keyboard insets, create-project) stay, restyled with these same tokens — never a parallel style. The mobile sidebar otherwise mirrors the desktop structure exactly (ui13 job 9): the same three icon tabs, the same footer taskbar at the natural bottom (safe-area padded), the same drawers — rendered as bottom sheets per the sheet law; no mobile-only sidebar views (the Running tab is gone — active sessions live in the planner/worker counter drawers on both form factors, and the quick-settings edge flyout is gone — its settings live in the Settings surface).
Mobile parity laws (ui7 phase 8): the mobile sidebar project/session rows are the same beUI ai-sidebar row anatomy as desktop (borderless `min-h-11 rounded-lg` rows — 44px-tall touch variant of the desktop `min-h-9` — icon tile, MarqueeLabel, count numeral, spring chevron), with actions always visible instead of hover-revealed; session actions open the bottom sheet (rename / move / copy / delete on token colorways). The mobile top bar is hamburger + tab rail only, on the pane-header bar chrome — the old chat-title block is gone on both form factors; titles live in the pane header. The sidebar refresh button is desktop-only; mobile refreshes by pulling the sidebar list down (`usePullToRefresh` + the indicator row in SidebarContent, `data-slot="pull-to-refresh"`). Touch laws on every mobile-reachable control: 44px minimum hit area — visually small controls keep their size and extend the tap area with the `touch-hit` utility (`src/index.css`, pointer-coarse only, requires `relative`); no action gated behind hover (fence hover reveals with `md:` or `touch:opacity-100`, never `sm:`); text inputs 16px below md (`text-base md:text-sm`) so iOS Safari never zooms on focus; bottom chrome pads `env(safe-area-inset-bottom)`; full-height mobile surfaces use `dvh`, never `vh`/`h-screen`.
- Mobile safe-area and nav spacing variables (`--mobile-nav-*`, `--safe-area-inset-*`) are defined in `src/index.css`; use them, don't hardcode offsets.
- Phone chrome (ui14 job 11): one switcher. The old top strip (hamburger + Chat/Worker tab rail, which scrolled sideways) is gone; on a phone every full-pane view — Planner, Worker, Files, Source Control — is topped by the same slim pane header (`data-slot="pane-header"`, `overflow-hidden`, nothing in it scrolls) carrying the menu button (`MobileMenuButton`) at the left and the window selector at the right (the chat/shell toggle that used to sit beside it is gone since ui17 job 8 — the taskbar's Shell segment is that switch). The top-most bar carries `.mobile-top-bar` (`src/index.css`: safe-area-inset-top plus `--header-base-padding`, in Safari and home-screen mode alike — the app shell's inline `top` bypasses the old PWA offset on `.fixed.inset-0`) — the sidebar header uses the same class on phones. The phone sidebar (`data-slot="mobile-sidebar"`) fills the app shell edge to edge (no partial drawer, no scrim), slides on the 320ms `cubic-bezier(0.77,0,0.175,1)` ramp both ways, and closes from the X in its header (`data-slot="mobile-sidebar-close"`) or by opening a chat. Keyboard: `index.html` keeps `interactive-widget=resizes-content` (Chrome for Android shrinks the layout viewport; WebKit ignores the key), and for iOS the app shell (`data-slot="app-shell"`) is pinned to the visual viewport by `AppContent`'s visualViewport hook (`--vv-top` / `--keyboard-height` from `offsetTop`, `height`, resize + scroll while the keyboard is up, a re-read on `focusout`), so the composer rides the keyboard's top edge; the composer's bottom padding is `--composer-bottom-pad` (home-indicator inset at rest, 8px under `html[data-keyboard="open"]`); programmatic refocus uses `focus({ preventScroll: true })`. Pane shell (`PaneShell`, `src/components/app/workspace/`): the shell toggle opens a terminal in the project's cwd resuming that pane's session (`claude --resume <provider id>`), the server pre-trusting the folder in this instance's config dir (`trustProjectForClaude`) so no trust prompt appears; while the session is mid-turn the toggle shows the transcript read-only instead (`data-shell-mirror`, prompt bar hidden, permission requests still shown, a `data-slot="pane-shell-busy"` status row) and the real shell takes over once the turn ends. While the shell view is open the pane's queued-draft idle flush is held (`holdQueuedFlush` through `ChatInterface`), so a turn ending never auto-sends into the session the terminal is about to resume; the draft flushes when the shell closes. Known constraint: the guard is one-way — once a terminal has resumed the session, a prompt typed into that terminal and a send from the same session on another device would both write the session file; the terminal stays cached server-side for 30 minutes after the view closes.
- Bottom taskbar (ui17 job 8): the phone's whole navigation is one bar at the bottom of the app shell (`MobileTaskbar`, `src/components/main-content/view/subcomponents/`, `data-slot="mobile-taskbar"` inside `data-slot="mobile-taskbar-slot"`), rendered by `MainContent` under `isMobile` for any project that has a worker (a standalone chat gets none). Segments are `flex-1 basis-0` label-only buttons — no icons, so they stay readable at any count: two split 50/50, three in thirds. Planner and Worker are always there; each tool window the user opens adds one more in the fixed order Files, Git, Shell. The active segment is monochrome ink only (`bg-accent/60 text-foreground`, the sidebar taskbar's mark) with `aria-current="page"` and `data-active`; segment membership and the active mark come from the pure `taskbarSegments()` (tested in `MobileTaskbar.test.tsx`), never from ad-hoc conditionals in the view. The window selector in the pane header is what opens and closes the tool windows on a phone: it lists Files, Source Control and Shell only, with a check on the open ones, and selecting an open one closes its segment (falling back to the last chat pane if that window was the visible one). The Shell segment replaces the active chat pane's transcript with its `PaneShell` terminal, so there is one mechanism, not a header swap button too; on the worker it also stands the jobs takeover down until you leave the segment. The jobs view is a full-screen takeover above the bar (`data-layout="pane"`), closed again from the header's job sign. Height is one variable, `--mobile-taskbar-height` in `src/index.css` (a 44px touch row plus the 1px top rule over `env(safe-area-inset-bottom)`), used by both the bar and its slot. Composer focus (`onInputFocusChange` wrapped in `MainContent`) sets `data-hidden="true"`: the slot's height collapses and the bar slides out together on the 300ms `cubic-bezier(0.77,0,0.175,1)` drawer ramp, so the keyboard rises against the composer and never against a dead band; blur restores both. While the bar is up it publishes `--mobile-taskbar-offset` on the document element, and phone chrome that pins itself to the screen bottom (the terminal's `TerminalShortcutsPanel` key bar) offsets by it instead of covering the segments. Nothing above the `md` breakpoint renders any of this — the desktop pane strip is untouched.
- Activity drawer routing on a phone (ui17 job 8): the sidebar footer's active-sessions drawer sends a worker row to the Worker segment, not to the planner pane — `Sidebar` calls `onOpenWorkerSession` (mobile only), the app selects that row's project, switches the tab to `worker`, and hands `WorkerPane` a `WorkerSessionRequest` (`{ sessionId, provider, token }`) which pins that run for the usual minute. Planner rows keep the ordinary session route. This is what keeps a worker run from opening under a "Planner" header.
- Notification-tap routing (audit1 job 4): every session notice deep-links its app session id. Dispatch, direct, external, and maintenance origins select the Worker slot and pin that run; planner origin selects the Planner slot. The URL carries the origin and provider as a cold-launch fallback, while an already-open client receives the same fields from the service worker.
