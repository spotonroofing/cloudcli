# Settings

- Settings: `src/components/settings/` (the old mobile quick-settings edge flyout is gone, ui13 job 9 — every form factor reaches these settings through the Settings surface). Settings is not a popup (ui13 job 5): it renders as content (`data-slot="settings-surface-content"` — title row with save status, then the tab strip (`data-slot="settings-tabs"`, ui14 job 5: `IconTabs` with sliders, palette and bell icons on the sidebar header's `px-3 pb-2 pt-3` row: System, Appearance and Notifications — no About tab, no text-label pill bar), scrolling body) on the full-sidebar surface shell, toggled by the taskbar's Settings icon (`data-slot="settings-trigger"`) and closed by Escape; no close X, no `modal-backdrop`. Opening it from the collapsed rail expands the sidebar first; on mobile `openSettings` also opens the sidebar overlay.
- Settings body (ui14 job 5): every tab is sections of rows in cards at the sidebar row scale — `SettingsSection` (`data-slot="settings-section"`, a `text-[10px] font-medium uppercase tracking-wide` muted heading, the AccountsPanel/ActiveSessionsDrawer label), `SettingsCard` (`rounded-lg border border-border/60 bg-card/40`, `divide-y` when divided), `SettingsRow` (`data-slot="settings-row"`, `px-3 py-2`, 13px label, 11px muted description, control at the right end; wraps below the text at sidebar width). Controls are the app's: `BeuiSwitch` via `SettingsToggle` for every on/off (no native checkboxes), `h-7` select triggers and inputs, `h-7 px-2 text-xs` outline buttons. Sections sit `space-y-5`, body padding `px-3 py-3`; no tab-level heading, no description paragraph, no oversized cards.
- Full-sidebar surface (ui13 job 5): `SidebarSurface.tsx` — the slide-up shell Settings (`data-slot="settings-surface"`) and Memory (`data-slot="memory-surface"`) fill the sidebar with. Not a centered popup, not a floating panel: no portal, no panel chrome — `absolute inset-0 z-20 bg-background` over the sidebar's content region (a `relative overflow-hidden` wrapper in `SidebarContent.tsx` covering the header + list, ending above the footer so the taskbar stays reachable), animating `y: 100% ↔ 0` on the ramped curve (0.32s EASE_IN_OUT both ways, reduced-motion honored). Escape closes in the shell; the surface's taskbar icon toggles; one surface at a time, and opening a footer drawer closes any open surface (`onDrawerOpened`).
- System tab (ui15 job 0, codex job 1; usage thresholds ui15 job 7): `SystemSettingsTab.tsx`, sections Sessions, Dispatch, Machine, Usage alerts and Models, each a `SettingsCard divided` of `SettingsRow`s. Every watchdog switch is a `SettingsToggle` whose description ends "Default on/off." and saves alone through `PUT /api/settings/watchdog` (optimistic, reverts on failure). The rotation threshold is the last Sessions row: a `h-7 w-16 px-2 text-xs` number `Input` (5 to 95) that commits on blur or Enter through the same PUT. Usage alerts has five matching inputs for account warning/urgent, fleet warning/urgent, and fleet 7-day; defaults are 75/90, 75/90, and 90, exhaustion remains fixed at 100, and each commits alone through `/api/settings/usage-alerts`. Models rows (`data-slot="model-default-pickers"`): a `w-40` model `Select` whose trigger and items lead with the provider mark (`LLMProviderLogo` at `h-3.5 w-3.5 opacity-60`, muted, icon-sized) before the catalog label, items listed per provider from `/api/providers/:provider/models` (Claude then Codex), then a `w-24` effort `Select` beside it with the composer's effort labels (High, Extra, Max); both `h-7 px-2 text-xs` triggers, saved together per role through `PUT /api/settings/models`; changing the model keeps the effort when the new model allows it, else takes that model's default effort.
- Planner MCP (ui15 job 0): the System tab adds one project-scoped `SettingsSection` when projects exist. A project `Select` appears when more than one project is available, followed by one standard `SettingsRow` and `SettingsToggle` per supported server. The stored allowlist defaults to spoton-core, spoton-sign and playwright; every other server starts off and can be enabled per project through `/api/settings/planner-mcp`.
- Sounds and obvious settings (ui15 job 5): Notifications keeps one master sound toggle and adds `data-slot="completion-sound-settings"`, with independently synced planner and worker completion `Select`s plus a compact outline preview button for each. Four short synthesized choices live in `notificationSound.ts`; successful completion events use the sound for the pane that owns the session and only the matching visible pane plays it. Appearance's light/dark row is a three-way System, Light or Dark `Select`; System follows `prefers-color-scheme`, and `theme-mode` syncs through the cloud settings store. Default model and effort already live under System, while send-on-enter remains under Appearance's Input settings.
- Web Push truthfulness (audit1 job 4): the Notifications row reads enabled only after the server acknowledges the browser subscription row. A failed key, subscribe, status, or unsubscribe response leaves the toggle in the server-confirmed state and puts the server's reason in the row description. iOS Safari outside Home Screen mode is detected before subscribe and the disabled row explicitly tells Willem to install the app to the Home Screen.
- Theme picker (ui15 job 6): Appearance's named-theme `Select` uses the shared `ThemePaletteDots` preview at 10px. The four-dot preview is right-aligned and visually hidden at rest, then fades in for the hovered or keyboard-focused option; labels keep the resting row to themselves. Every catalog entry remains a full layered light/dark token pair as specified in Tokens.
